# 확장 디자인 검사 검증 준비

이 문서는 새 맵시 소스로 setup과 lint를 검증할 때 사용합니다. [가상 프로젝트](../test/fixtures/design-audit/DESIGN.md), [검사 항목 17개](../test/fixtures/design-audit/cases.json), 보고서 결과 검사 명령을 준비했습니다. 준비·단위 테스트와 실제 에이전트·브라우저 수행을 구분합니다.

## 실행 환경 준비

저장소의 기존 체크아웃에서 다음 명령을 실행합니다. 외부 패키지·서비스·계정은 필요하지 않습니다.

```bash
node --test test/*.test.mjs
python3 -m http.server 0 --bind 127.0.0.1 --directory test/fixtures/design-audit
```

서버가 출력한 포트를 사용해 `/index.html?view=reference`와 `/index.html?view=target`을 엽니다. 포트는 자동 배정하므로 다른 서버를 중지하지 않습니다. 종료할 때 자신이 띄운 프로세스만 종료합니다. 화면의 상태·테마·긴 이름·모달·지연 안내 제어와 브라우저의 화면 크기·움직임 감소 설정을 사용합니다.

새 화면으로 이동한 뒤에도 실제 화면 크기와 `matchMedia('(prefers-reduced-motion: reduce)').matches` 등을 확인합니다. 도구가 설정을 유지했다고 가정하지 않습니다. 비교 모달은 닫기 버튼 하나만 있는 검증용 구성으로 Tab·Shift+Tab 모두 그 버튼에 머무르는 것이 기대 결과입니다.

이 화면은 이 가상 폴더의 자료만 읽고 모든 입력 확인을 메모리에서 처리합니다. 실제 서비스의 저장·제출·삭제 동작을 재현하지 않습니다.

## setup 검증

1. fixture 파일을 수정하지 않는 점검을 요청합니다. DESIGN과 컴포넌트 문서의 상태·근거·보완 제안을 보고하게 합니다.
2. 문서가 있다는 이유로 점검을 생략하지 않는지, 컴포넌트 가이드의 `retired-guide.md` 참조가 끊겨 있다는 점을 찾는지 확인합니다. 이 링크는 검증용 의도된 결함입니다.
3. 간격·중첩·배치·선택 이유·상태·조작·변화 조건을 기존 DESIGN과 연결하는지 확인합니다. 명시적으로 허용한 pill과 반경 변형은 새 규칙으로 덮어쓰지 않아야 합니다.
4. 문서 보완 자체를 검증할 때는 저장소 안의 `.git/mapsee-setup-verification-<실행 ID>/`에 가상 폴더만 복사해 setup을 실행합니다. 명령의 작업 경로는 기존 체크아웃을 유지하고 원본 fixture와 평가 기준은 보존합니다. 끊긴 링크는 추측한 경로로 바꾸지 않고 후속 결정을 남기는 것이 가능합니다.

## lint 검증 요청

평가할 에이전트에는 새 lint 스킬과 가상 프로젝트·cases.json을 제공합니다. [기대 판정](../test/design-audit.expectations.json)과 이 문서의 setup 정답은 제공하지 않습니다. 설치본을 검증한다면 실제 읽은 스킬 경로·버전·파일 해시를 남기고 새 소스와의 일치를 확인합니다.

```text
맵시 lint로 제공된 가상 프로젝트를 검사해줘.
DESIGN.md와 cases.json의 17개 ID·검사 축·조건을 유지해줘.
target 화면의 사용 적합성과 reference 화면과의 일관성을 검사해줘.
원본 파일은 수정하지 말고, 보고서는 지정한 새 경로에 JSON으로 저장해줘.
코드에서 확인한 근거와 실제 화면·조작 근거를 구분해줘.
실행할 수 없는 상태는 미측정으로, 확정 기준이 없는 의견은 판단 필요로 남겨줘.
```

브라우저가 없으면 정적 검사를 진행하고 실제 재현이 필요한 9개 항목은 미측정으로 남깁니다. 이 실행은 전체 검증 완료가 아닙니다.

## 보고서 확인

```bash
node test/check-audit-report.mjs /보고서의/절대경로.json
```

| 종료 코드 | 의미 |
| --- | --- |
| `0` | 17개 항목의 판정·검사 축과 요구한 근거 종류가 시나리오와 일치합니다. |
| `2` | 보고된 미측정 항목이 있어 검증이 남았습니다. |
| `1` | 기대와 다른 판정·누락·불필요한 항목·근거 부족 또는 입력 오류입니다. |

이 명령은 보고서를 검사하며 브라우저를 실행하지 않습니다. 근거가 실제 수집된 것인지, 계획한 조건과 실제 조건이 맞는지는 로그·DOM 측정·화면·키 입력 기록과 직접 대조합니다. 기대 판정 JSON만 복사한 결과로 수행을 인정하지 않습니다.

명시적으로 허용된 pill은 독립적인 사용의 적합성을 `match`로 보고하거나, 중첩 반경 규칙만의 적용 여부를 `not-applicable`로 보고할 수 있습니다. 둘 다 원본 근거가 있어야 하며 검증기는 이 차이를 오판으로 세지 않습니다. 위반으로 만드는 판정은 허용하지 않습니다. `matched`는 기대한 불일치·검토·예외를 올바르게 구분했다는 뜻이며 가상 화면의 디자인 적합성 통과를 뜻하지 않습니다.

## 실제 수행 시 남길 자료

- 사용 클라이언트·스킬 경로·버전·소스/설치본의 동일성, 코드·기준 문서·fixture 식별 근거.
- 계획한 상태와 실제 상태, 브라우저·화면 크기·확대·테마·언어·움직임 설정과 확인하지 못한 조건.
- 17개 ID의 판정과 원본 근거, 키보드·값 보존·영역 측정·시간에 따른 배치 변화의 실제 기록.
- 원본/집계 JSON, 위 명령의 결과, 검사 전후 입력 해시와 변경 여부.

서로 다른 클라이언트의 실제 수행은 따로 기록합니다. 스킬 형식·단위 테스트·fixture 준비가 끝났다는 사실로 Claude·Codex의 새 지침 수행이나 실제 화면 검증을 완료 처리하지 않습니다.

## 공용 컴포넌트 재사용의 정적 회귀

[별도 가상 프로젝트](../test/fixtures/component-reuse/DESIGN.md)의 [계획 10개](../test/fixtures/component-reuse/cases.json)는 공용 컴포넌트 대신 일반 DOM을 만든 경우와 호출 경로·역할을 대조합니다. JSX 소스는 정적 검사 입력이며 React 의존성·타입·빌드·실제 렌더를 검증한 자료가 아닙니다.

검사할 역할은 주요 제출·정보 표면, 이름과 속성의 모방, 별칭과 재내보내기·앱 래퍼, 레이아웃 DOM과 라이브러리 구현, 대응 구현이 없는 역할, 재사용 기준이 미확정인 기존 영역과 변형 선택입니다. 모든 DOM을 금지하거나 컴포넌트 이름·import 존재만으로 적합성을 판단하지 않는지 확인합니다.

평가할 에이전트에 해당 폴더와 새 lint 스킬만 제공합니다. 10개 ID·축을 유지한 정적 검사를 요청하고 원본을 수정하지 않게 합니다. [기대 판정](../test/component-reuse.expectations.json)·검증기·테스트 코드·이 문서·과거 결과는 평가 입력에서 제외합니다. 기준·실제 호출부·원천 구현의 근거를 확인합니다.

```bash
node test/check-audit-report.mjs /보고서의/절대경로.json component-reuse
```

두 번째 인자를 생략하면 기존 `design-audit` 17개 시나리오를 사용합니다. 알려지지 않은 이름은 실패로 처리합니다. 종료 코드 0·2·1의 의미와 원본·해시·근거의 보존 원칙은 위와 같습니다. 이 선택 기능도 보고서를 확인하며 소스의 DOM·JSX를 자동 분석하지 않습니다.

허용된 레이아웃 DOM과 대응 공용 구현이 없는 역할은 직접 사용의 `match` 또는 재사용 의무의 근거 있는 `not-applicable`로 보고할 수 있습니다. 둘 다 원본 출처와 이유를 확인하며 `mismatch`는 허용하지 않습니다. 라이브러리 구현에 화면 호출부 규칙이 적용되지 않는 항목은 계획한 범위대로 적용 제외합니다.

## 분기·전달·복합 구성과 setup 재실행

[가상 프로젝트](../test/fixtures/component-contracts/DESIGN.md)의 [계획 8개](../test/fixtures/component-contracts/cases.json)를 같은 방식으로 검사하고 `component-contracts`를 선택합니다. 평가 에이전트에는 해당 자료와 설치 스킬만 제공합니다. [기대 판정](../test/component-contracts.expectations.json)과 검증기·테스트·과거 결과는 제공하지 않습니다. 기본 분기 외의 DOM 대체, 공개한 disabled·이벤트 전달 누락, 라벨·오류 연결을 찾는지 확인합니다. 정상 전달과 의도적으로 공개하지 않은 속성을 위반으로 만들지 않는지도 대조합니다.

setup은 복사한 [기존 가상 자료](../test/fixtures/component-reuse/DESIGN.md)에서 사용 기준을 정리한 뒤, 같은 요청으로 새 세션에서 다시 실행합니다. 첫 수행의 변경 경로·기존 결정 보존을 확인하고, 두 번째 수행 전후의 전체 입력 해시를 비교합니다. 미결정 상태를 그대로 유지하며 보완할 내용이 없으면 파일이 바뀌지 않아야 합니다. 실제 엔강대 문서는 점검 전용으로 확인합니다.

실제 FormField·Input·오류·Dialog는 정적 연결과 브라우저의 진입·Tab·Shift+Tab·Escape·초점 복귀·실패 복구를 나눠 확인합니다. 버전·대상 커밋·설치본·적용 결과와 다음 검사는 [버전별 적용 절차](version-validation.md)에 따라 기록합니다.

## 누락·스타일 재정의·결과 이력

[스타일 자료](../test/fixtures/style-overrides/DESIGN.md)의 [계획 8개](../test/fixtures/style-overrides/cases.json)와 설치 스킬만 평가 에이전트에 제공합니다. 기대 판정·검증기·테스트·과거 결과는 제외합니다. 스타일 덮어쓰기의 고정 계약과 허용된 너비·plain을 구분하는지 `node test/check-audit-report.mjs <보고서.json> style-overrides`로 대조합니다. 이는 정적 평가이며 실제 CSS 계산·조작은 별도입니다.

보고서에는 발견한 페이지·사용처·상태와 검사 ID를 inventory로 연결하고 검색 범위·한계를 남깁니다. 연결 없는 대상, 없는 검사 ID, 중복 ID와 미검사 대상이 남은 complete를 검증기가 구분해야 합니다. 기준이 부족한 review의 수집 완료와 적합률을 혼동하지 않는지도 확인합니다.

같은 프로젝트의 이전·현재 보고서를 `node <lint>/scripts/compare.mjs <이전.json> <현재.json>`로 대조합니다. ID가 빠지거나 미측정인 문제를 해결로 만들지 않는지, 기준·대상·기대값·방법·조건이 바뀌면 비교 불가로 남기는지 검사합니다. 비어 있는 조건과 대상 식별이 없는 경우도 해결로 인정하지 않습니다.

엔강대에서는 같은 커밋의 이전 항목을 다시 수행하고, 다른 URL의 대응 역할을 추가합니다. 기존 기준·ID의 재사용과 화면·조작의 새 수행을 구분하며 전체 라우트·모든 사용처 검증으로 표시하지 않습니다. setup의 미결정 항목은 실제 부모·자식·간격과 모달 역할에 맞는 제안을 만드는지 확인하되 프로젝트 규칙으로 자동 채택하지 않습니다.

## 근거 연결·문제 분류·변경 영향

새 보고서는 [강화 연결](../plugins/mapsee/skills/lint/references/quality.md)을 사용합니다. 다른 URL·요소·상태·화면 조건·기준 식별자의 근거가 연결되면 완료로 세지 않는지 확인합니다. 원시 수집 ID·파일 해시·내용과 판정을 수행자가 대조하며 메타데이터 검사만으로 원본 진위를 보증하지 않습니다.

실제 측정이 아닌 합성 보고서와 원시 캡처를 평가 에이전트에 제공합니다. 의도한 답·기대 판정·테스트·이전 결과를 제외하고, 확인 가능한 판정과 제공되지 않은 상태를 구분하는지 확인합니다. 원본은 보존하고 파생 보고서의 미측정·근거·영향 분류를 대조합니다.

문제 그룹은 실제 과업 영향과 기준의 확실성을 구분하는지, 같은 이름만 가진 다른 원인을 묶지 않는지 확인합니다. 재검사 제안은 실제 변경과 가상 입력을 구분하고, 미연결 파일·표본 밖 영향·선택 0개를 숨기지 않아야 합니다.

실제 UI는 소스의 전환점 직전·해당 값·직후와 긴 입력·오류·확대 표본을 확인합니다. 정상적인 내부 스크롤과 접근 불가능한 잘림을 구분합니다. 실제 배율·뷰포트·동작을 확인하고 핀치 확대·데스크톱 페이지 확대·320 CSS px 조건을 같은 검사로 표시하지 않습니다.

## 배치 영역·연속 흐름·원본 검사

[부모 영역별 기준](../plugins/mapsee/skills/lint/references/placement.md)은 같은 뷰포트의 본문·좁은 모달 등 실제 영역에서 확인합니다. 부모 경계·content box·여백과 사용한 크기·변형을 구분합니다. 같은 역할의 허용 차이를 새 위반으로 만들지 않습니다.

[연속 상태 전환](../plugins/mapsee/skills/lint/references/transitions.md)은 요청별 도착·해제 순서와 단계별 입력·오류·잠금·초점을 보존합니다. 실패→재시도→합성 성공, 대기 중 닫기와 화면 이탈 뒤 조회 응답을 선택해 검사합니다. 요청 개수는 원시 기록에서 확인하고 근거 없는 고정 개수 가정으로 화면 문제를 만들지 않습니다.

[원본 묶음 검사](../plugins/mapsee/skills/lint/references/evidence.md)는 정상 파일·누락·파일 교체·잘못된 Pointer·내용 차이·문맥 차이·기준 해시 차이와 입력 보존을 확인합니다. 바깥 경로·심볼릭 링크·형식 오류도 구분합니다. 원본 검사가 통과해도 미측정 판정·실행 상태를 승격하지 않습니다.
