## 검사 지침과 가상 자료

검사기·패키지 단위 검사 35개가 통과했습니다. 새 시나리오 8개는 상태 분기에서 공용 컴포넌트를 우회하는 경우, 공개 disabled·이벤트 누락, 라벨·오류 ID 연결과 정상 전달·구성·의도적인 API 제한을 대조합니다.

기대 판정·검증기·테스트·과거 결과를 제공하지 않은 Codex가 설치본과 소스를 읽어 불일치 5·일치 3으로 판정했습니다. 8개 모두 기대 판정과 일치했고 검증기는 `matched`, 미측정은 0입니다. 일치율 37.5%는 의도적 결함을 넣은 가상 자료의 값이며 정확도나 엔강대 품질 점수가 아닙니다. 입력 28개 파일의 해시가 보존됐습니다.

setup은 기존 가상 자료를 복사한 폴더에서 DESIGN 하나만 보완했습니다. 역할별 사용 기준과 기존 원본을 연결하고 관찰·미결정을 분리했습니다. 첫 실행은 기존 본문을 보존하고 DESIGN만 변경했습니다. 같은 요청으로 새 세션에서 두 번째 실행했을 때 파일 8개 모두 바뀌지 않았습니다. legacy의 의무와 새 상태 기준을 확정하지 않고 두 실행 모두 부분 구성으로 보고했습니다. 이는 한 표본의 재실행 결과이며 모든 프로젝트의 불변성을 보증하지 않습니다.

## 엔강대 setup 점검

문서 상태·공개 API·대표 호출 경로와 역할별 사용 기준을 보고서에 정리했습니다. DESIGN의 공용 UI 사용 의무와 특정 이름의 독점 사용 여부를 구분했습니다. plain 버튼, URL 이동용 링크와 숨은 native input을 허용 범위로 남겼으며, 별도로 명시된 권장 강도가 없다는 점도 보고했습니다.

대상 가이드의 라벨 ID·단위 여백·속성/ref 전달·오류와 생성 중 책임은 확인했습니다. Players·Home·컴포넌트 지도에는 현재 공개 Input·plain ActionButton·호출자 조합의 연결 설명 보완을 제안했습니다. Dialog에는 semanticId와 닫힘 중 inert·aria-hidden 설명, Rule Card에는 실제 스타일 정본 연결이 필요했습니다.

Storybook의 준비 예제는 native input과 비활성 표시를 사용하며 실제 앱의 Input 전달·aria-busy 경로 전체를 재현하지 않습니다. 이를 제품 위반으로 단정하지 않고 예제 검증 범위의 차이로 남겼습니다.

기존 여백·역할별 크기는 확정 기준으로 연결했습니다. 부모 반경에서 안쪽 거리를 빼는 중첩 라운드 관계, Rule 공간 구성의 선택 이유와 일부 환경 조건은 미결정입니다. 스킬의 예시 공식을 새 프로젝트 규칙으로 만들지 않았습니다. 점검 보고는 완료했고 setup 상태는 부분 구성입니다. 엔강대 문서·wiki는 수정하지 않았습니다.

## 실제 컴포넌트 구성과 조작

| 항목 | 관찰과 판정 |
| --- | --- |
| FormField·Input 연결 | A/B 라벨이 각각 실제 입력을 가리킵니다. 공개 구현을 거쳐 id·required·ref가 전달됩니다. 일치입니다. |
| 입력 초점 순서 | 진입 시 A, Tab으로 B, Shift+Tab으로 A에 이동했습니다. 일치입니다. |
| 빈 필수 입력 | 빈 이름 제출은 A 입력으로 이동하고 생성 요청이 발생하지 않았습니다. 일치입니다. |
| 대기 중 잠금 | 입력 두 개와 이전·제출이 잠기고 aria-busy 및 만드는 중 문구를 표시했습니다. 추가 Enter 뒤에도 합성 요청은 1개였습니다. 일치입니다. |
| 실패 복구 | 합성 실패 후 이름이 유지되고 alert와 조작 복구를 확인했습니다. 이름 수정 뒤 오류가 해제됐습니다. 일치입니다. 서버 오류를 개별 필드 오류로 강제 연결하지 않았습니다. |
| Dialog 이름·닫기 | 경기 규칙 이름의 dialog가 표시되고 Escape로 닫혔습니다. 일치입니다. |
| Dialog 초점 관리 | 열림 후 초점이 경기 룰 버튼에 남았습니다. Tab은 배경의 월페이퍼·강습전으로 이동했고 Shift+Tab도 배경으로 이동했습니다. 내부 summary에 초점을 두고 Escape로 닫으면 body에 남았습니다. 기존 가이드에도 가두기·복원 부재가 기록돼 있어 검토 1개로 묶었습니다. |
| 중첩 라운드 | 개별 반경은 있지만 관계·조건·예외가 채택되지 않았습니다. 숫자만으로 위반을 만들지 않고 검토 1개로 남겼습니다. |

Dialog 초점 문제는 새로 생긴 회귀라고 주장하지 않습니다. 새 검사로 기존 한계를 실제 키 입력에서 재현한 결과입니다. 모달 초점 정책을 확정한 뒤 진입·내부 이동·복귀와 배경 차단을 함께 보완할 수 있습니다. 이번 맵시 작업에서 제품을 수정하지 않았습니다.

## 화면 간 일관성과 집계

같은 URL의 경기 설정·참가자 입력 스텝을 같은 준비 폼 역할로 비교했습니다. 별도 라우트 전체 비교나 화면 픽셀 유사도는 아닙니다. 같은 1440×1000·dark·비호버·전환 완료 조건에서 제목과 주요 행동을 대조했습니다. 진입 직후 호버/전환 중 색은 최종 비교에 사용하지 않았습니다.

제목은 Ria 48px·줄 높이 60px로 같았습니다. 주요 버튼은 높이 64px·padding 16px 40px·pill, Wanted Sans 20px·노랑 배경과 어두운 글자로 같았습니다. 역할이 다른 설정 수치와 이름 입력의 크기를 같게 강제하지 않았습니다.

컴포넌트 사용은 일치 6·검토 2로 적합률 `6/6 = 100%`, 커버리지 `6/8 = 75%`입니다. 화면 간 비교는 일치 3으로 `3/3 = 100%`, 커버리지 100%입니다. 미측정 항목은 선택한 범위에서 0이며 실행 상태는 complete입니다. 남은 검토와 표본 밖 미검증 범위를 전체 수용으로 계산하지 않습니다.

원시 CLI 출력·수정 전후 해시·setup 두 결과·사용 기준표·브라우저 JSON·키 입력·스크린샷·보고서·검증 결과는 로컬 `.git/mapsee-070-20261123-1jz6fyma/`에 보존합니다. 실제 문서 점검과 화면 결과의 수집자를 구분하고, 기대 판정 자료를 평가 실행에서 읽지 않은 것을 명령 기록과 대조했습니다.

대상 worktree의 입력 2,045개와 공유 체크아웃의 입력 1,951개는 실행 전후 해시·HEAD·Git 상태가 같았습니다. 설치된 스킬 자료 12개도 후보 소스와 같았습니다. 자신의 브라우저·서버를 종료하고 detached worktree를 정상 제거했습니다. 스킬 3개의 형식 검사·패키지 검사와 문서 링크·150줄 제한도 확인했습니다. 이전 가상 자료에 의도적으로 남긴 깨진 가이드 링크 1개는 보존했습니다.

실제 DB 저장 성공·다른 화면·동작 줄이기·물리 터치 기기·화면 읽기 프로그램·전체 경기 E2E·Claude 모델 실행은 이번 검증에 포함하지 않습니다. 공개 원격 반영·CI와 운영 배포도 별개입니다. 이전 0.6.0 화면 결과를 이 커밋의 수용 근거로 재사용하지 않았습니다.
