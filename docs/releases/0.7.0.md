# 맵시 0.7.0 배포 후보

0.6.1에서 준비한 일반 DOM 대체 검사를 포함하고 setup과 복합 구성 검사를 확장한 마이너 후보의 기록입니다. 이후 보강은 [0.8.0 후보](0.8.0.md)로 이어집니다. 로컬 설치·실제 프로젝트 적용과 원격 배포 상태를 구분합니다. 앞선 [0.6.1 후보](0.6.1.md)와 검증 자료는 보존합니다.

## 변경 내용

- setup이 역할·공용 컴포넌트·공개 경로·필수/권장/허용/미결정·조건·예외·출처를 연결합니다. 명시적인 의무가 없으면 공용 컴포넌트가 존재한다는 이유로 필수로 만들지 않습니다.
- 같은 입력과 결정으로 setup을 재실행할 때 기존 항목을 재사용하고 중복·불필요한 변경·관찰의 규칙 승격을 피합니다.
- lint가 상태별 렌더 경로와 공개한 disabled·이벤트 등의 전달을 추적합니다. 의도적으로 제공하지 않은 속성을 전달 누락으로 만들지 않습니다.
- FormField·Input·오류의 연결과 Dialog의 열기·이동·닫기·초점 복귀를 구분해 검사합니다. 개별 컴포넌트를 사용했다는 사실만으로 조합과 실제 조작까지 정상 판정하지 않습니다.
- 새 정적 시나리오 8개와 검증기의 `component-contracts` 선택, [버전별 엔강대 적용 절차](../version-validation.md)를 추가했습니다.

## 호환성과 적용

이름 mapsee, setup·document·lint, 두 검사 축과 보고서 schemaVersion 1을 유지합니다. 기존 검증 명령의 기본 시나리오도 유지합니다. 두 플랫폼의 매니페스트 버전은 0.7.0입니다.

범용 JSX 분석기나 제품 자동 수정기는 추가하지 않았습니다. 에이전트가 원본 기준과 소스를 읽어 판정하고 집계 도구가 수치를 계산합니다. lint는 보고 전용이며 setup 점검 모드도 원본 문서·wiki를 수정하지 않습니다.

## 검증과 배포 상태

검사기·패키지 테스트 35개와 설치본의 정적 판정 8개를 확인했습니다. setup 작성·재실행과 엔강대의 실제 화면 적용 결과는 [0.7.0 검증 기록](../verification/0.7.0.md)에 있습니다. 가상 결함의 일치율을 도구 정확도나 제품 품질 점수로 쓰지 않습니다.

Codex의 `mapsee@mapsee`에는 로컬 후보를 설치해 적용했습니다. 영구 Git 마켓플레이스 주소를 바꾸지 않고 한 번의 설치 명령에 로컬 소스를 지정했습니다. 이전 0.6.1 로컬 네임스페이스는 설치 자료를 보존하고 비활성화해 중복 호출을 방지했습니다. 공개 Git 원격 반영·태그·GitHub Release·CI와 Claude 모델 실행은 이 로컬 적용 결과에 포함하지 않습니다.
