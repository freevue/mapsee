# 맵시 0.12.0 배포 후보

토큰의 역할·참조 경로, 표시와 실제 선택 상태, 강제 색상 환경의 구별·초점을 보강했습니다. [0.11.0](0.11.0.md)과 이전 자료는 유지합니다.

## 변경 내용

- setup은 기존 가이드의 역할 토큰·로컬 별칭·활성 fallback과 허용 예외를 연결합니다. 값이 같다는 이유로 역할을 합치거나 필수 오타와 선택적 토큰 부재를 같은 문제로 만들지 않습니다.
- lint는 실제 속성·원본·적용 스코프·계산값을 대조합니다. 빌드 지시문과 실행 CSS를 구분하며 같은 색에 가려진 역할 오용을 확인합니다. 범용 CSS/AST 분석기를 추가하지 않았습니다.
- 선택 표시는 native checked·aria-pressed/selected·연결 콘텐츠·초점·지원 조작과 함께 확인합니다. 수동 탭의 초점 이동과 활성화를 구분하고 native 라디오에 탭 계약을 강제하지 않습니다.
- 강제 색상의 active 여부·실제 키보드·선택·포커스를 확인합니다. 사용자 색상 변경을 토큰 위반으로 취급하지 않으며 실제 OS와 브라우저 모의·지원 미결정을 구분합니다.
- 기존 보고서 검증기에 semantic-contracts 10개 계획을 연결했습니다. 실제 소스·화면 수집과 검증기의 기대 판정 대조는 별개입니다.

## 검증과 적용

테스트 80개·세 스킬 형식 검사와 패키지 검사를 통과했습니다. 가상 화면·소스의 10개 항목은 정상 5·의도한 위반 4·미결정 1로 구분했습니다. 실제 수동 탭·강제 색상 포커스와 동일한 색의 서로 다른 토큰을 확인했습니다.

엔강대는 새 develop `6919ed26874eaf79f2af95a77949c764c5a022f3`에 고정했습니다. 일반 화면에서 토큰 참조, 라디오의 방향키·checked·입력 잠금/복구와 대진 승리의 Space·pressed·문구·아이콘을 확인했습니다. 두 URL의 공용 primary 변형 색 참조도 대조했습니다.

강제 색상 모의에서 라디오 선택 구별, 라디오 포커스, 다음 버튼 포커스의 소실을 관찰했습니다. 지원 범위의 명시적 채택을 확인하지 못해 실제 과업 영향이 있는 review 3개로 남겼습니다. 실제 8항목은 일치 5·검토 3이며 제품 코드는 수정하지 않았습니다. [적용 검증](../verification/0.12.0.md)에 범위·근거·한계를 기록했습니다.

## 호환성과 남은 범위

플러그인 이름·세 스킬·report schemaVersion 1·기존 두 축·산식·원본 묶음·준비 기록 형식은 유지합니다. Codex 설치본은 로컬 0.12.0입니다. 기준·제품·위키를 자동 수정하지 않습니다.

실제 Windows OS·전체 팔레트·음성 출력·표본 밖 동작·전체 게임 회귀·실제 DB·Claude·독립 모델·원격 CI·운영 수용은 미검증 또는 범위 밖입니다. 커밋·푸시·공개 배포 전 로컬 후보입니다.
