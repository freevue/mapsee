# 버전별 엔강대 적용

맵시의 기능을 보강할 때 버전을 올리고 엔강대에서 적용 결과를 확인합니다. 맵시의 검사 지침과 엔강대의 제품 규칙은 각각 원래 저장소가 소유합니다. 엔강대의 예외·값을 맵시 공통 규칙에 복사하지 않습니다.

## 버전 준비

1. 두 플랫폼의 plugin.json에 같은 버전을 지정합니다. 1.0.0 이후에는 [호환성 계약](../plugins/mapsee/COMPATIBILITY.md)에 따라 호환 수정은 패치, 호환 기능 추가는 마이너, 공개 계약의 호환되지 않는 변경은 메이저로 구분합니다.
2. 변경된 판단을 재현하는 최소 자료와 회귀 검사를 실행합니다. 가상 자료의 기대 판정은 실제 에이전트에 제공하지 않습니다.
3. Codex 설치 경로·버전과 검사에 쓰는 스킬 파일의 동일성을 확인합니다. 같은 플러그인의 다른 네임스페이스가 활성화돼 있으면 실행 범위를 명시해 구별합니다.

## 실제 적용

| 단계 | 수행과 결과 |
| --- | --- |
| 대상 고정 | 원격 develop과 공유 체크아웃의 차이를 확인하고 실제 사용할 커밋을 기록합니다. 공유 작업을 옮기거나 갱신하지 않고 필요하면 자신의 detached worktree를 사용합니다. |
| setup 점검 | DESIGN·컴포넌트 설명·공개 API·대표 호출부를 대조합니다. 역할별 필수·권장·허용·미결정과 조건·예외·출처를 보고합니다. 엔강대 문서·wiki는 수정하지 않습니다. |
| setup 작성 검증 | 별도 가상 복사본에서 문서를 보완하고 같은 요청으로 두 번 실행합니다. 두 번째 실행의 중복·결정 변경·불필요한 파일 변경을 확인합니다. |
| lint 적용 | 발견한 페이지·사용처·상태를 검사 ID에 연결하고 검색 한계·범위 밖·누락을 남깁니다. 이번 버전의 실제 화면·상태에서 선택·전달·구성·스타일과 다른 URL의 동등 역할을 비교합니다. |
| 실제 조작 | 정적 선언으로 확인할 수 없는 항목만 브라우저에서 재현합니다. 제품 저장은 합성 응답 등 분리한 조건으로 확인하며 운영 저장 성공과 구분합니다. |
| 결과 보존 | 버전·커밋·검사 범위·환경·판정·비율·남은 결정을 `docs/verification/<버전>.md`에 기록합니다. 배포 노트와 README에서 연결합니다. |
| 이전 결과 비교 | 같은 역할·규칙·상태의 ID를 유지합니다. 새 불일치·해결·남은 문제·미재검사·기준 변경을 원본 보고서와 대조합니다. 누락·예외·조건 변경을 해결로 만들지 않습니다. |
| 근거·후속 제안 | 대상·상태·조건·기준과 수집 ID·원시 자료를 연결합니다. 문제는 영향과 공통 원인으로 묶습니다. 실제 변경·가상 시나리오와 미연결 변경·표본 밖 영향을 구분해 재검사 목록을 제안합니다. |
| 배치·연속 흐름 | 화면 너비와 실제 부모 content box를 구분합니다. 해당 흐름의 조작·요청·응답 순서를 기록하고, 중간 상태나 마지막 화면만으로 전체 복구·중단 처리를 완료시키지 않습니다. |
| 원본 묶음 | verify-evidence.mjs로 보존한 파일 해시·JSON Pointer·기준·보고서 연결을 대조합니다. 문제를 찾으면 기존 complete와 함께 그대로 인계하지 않고 해당 근거를 교정·재수집하거나 미측정으로 남깁니다. |
| 수집·실제 재현 | 정지 비교는 대상·조상·선택 자산과 실제 연속 관찰 구간을 확인합니다. 키보드·부유 UI는 실제 재현·합성·부재·미측정을 구분하며 도구의 준비 검사를 제품 적합률에 더하지 않습니다. |
| 의미·선택·색상 환경 | 토큰 역할·별칭·활성 대체값과 실제 선택·활성 콘텐츠를 대조합니다. 강제 색상의 active·재현 수준·표시·의미·조작을 함께 보고하고 미채택 정책은 임의로 확정하지 않습니다. |

공용 서버·포트를 빌려 쓰지 않습니다. 자신의 서버·의존성·캐시를 사용하고 실제 화면 크기와 글꼴 로딩을 확인합니다. 실행 전후 입력 해시와 Git 상태를 대조합니다. 원시 JSON·스크린샷·조작 로그는 비공개 로컬 `.git` 아래에 보존하고, 공개 문서에는 비밀값이나 개인 환경 내용을 포함하지 않습니다.

검사에서 발견한 제품 문제는 원본 근거와 최소 개선 제안으로 보고합니다. 맵시 검사의 적용을 제품 코드·wiki 수정이나 원격 배포 권한으로 해석하지 않습니다. 이 작업은 자동 스케줄이나 실행 훅을 설치하지 않습니다.

## 완료와 남은 범위

단위 검사·가상 정적 판정·setup 작성·실제 프로젝트 정적 검사·브라우저 조작·설치본·원격 CI·운영 수용을 구분합니다. 새 소스로 확인하지 않은 항목은 과거 결과가 있어도 새 버전의 통과로 처리하지 않습니다. 동일한 입력 근거를 재사용했다면 해시와 범위를 밝힙니다.

각 버전의 검사 커버리지는 그때 계획한 표본의 비율입니다. 표본이 다르면 일치율의 증감만으로 품질이 좋아졌다고 하지 않습니다. 판단 필요·미측정·적용 제외와 실행 오류는 집계에서 숨기지 않습니다.

자신이 띄운 브라우저·서버를 종료하고 입력 보존을 확인합니다. 검증 자료를 보존한 뒤 자신의 worktree를 정상 제거합니다. 커밋·푸시·원격 CI·공개 설치 갱신은 실제로 수행했을 때만 완료로 기록합니다.

현재 배포 검증은 [1.1.0](verification/1.1.0.md)이며 이전 [1.0.0](verification/1.0.0.md), 재사용한 실제 화면 표본은 [0.12.0](verification/0.12.0.md), 이전 표본은 [0.11.0](verification/0.11.0.md)과 [0.10.0](verification/0.10.0.md), 검증 명령은 [검증 준비](verification-plan.md)를 따릅니다.
