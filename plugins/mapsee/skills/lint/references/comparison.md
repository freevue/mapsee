# 비교와 집계 규칙

## 무엇을 한 항목으로 세나요?

컴포넌트 검사는 대상 사용 위치와 적용 규칙의 조합입니다. 페이지 검사는 대상 페이지의 동등한 역할과 적용 규칙의 조합이며 비교 페이지를 근거로 연결합니다. 예를 들어 검색 화면의 주요 버튼이 공용 ActionButton을 사용하는지는 한 항목, 설정 화면의 같은 역할과 크기가 일치하는지는 다른 항목입니다. 같은 항목에 참고 페이지를 추가해도 항목 수를 늘리지 않습니다.

두 검사 축은 별도 비율을 냅니다. 종합 점수나 심미 점수를 만들지 않습니다. 같은 사실을 정적 검사·DOM·스크린샷으로 확인해도 항목을 늘리지 않습니다. 공통 원인이 여러 위치에 있으면 영향 위치는 모두 기록하되 같은 문제의 지적 수와 검사 항목 수를 구분합니다.

[간격·중첩·배치·선택 이유](composition.md)도 두 축 안에서 검사합니다. 특정 위치의 선택·배치·여백·라운드가 기준에 맞는지는 컴포넌트 사용 항목이며, 페이지 간 동등한 역할의 관계가 일관되는지는 페이지 비교 항목입니다. 프로젝트가 채택한 관계와 예외를 비교하고 반경·간격의 원시값이 다르다는 이유만으로 불일치로 세지 않습니다. 근거 없는 선택 이유는 `review`로 남깁니다.

항목 목록과 비교 대상을 먼저 정하고, 확인하지 못한 항목을 삭제하지 않습니다. 표본 검사라면 표본 페이지·컴포넌트·항목 수와 제외 범위를 밝힙니다. 그 비율을 서비스 전체 비율로 표현하지 않습니다.

## 비교 대상 선택

사용자가 지정한 페이지를 우선합니다. 지정이 없으면 공통 레이아웃·컴포넌트·기능 역할을 공유하는 페이지를 고르고 이유를 기록합니다. 대표 페이지라는 이유만으로 그 구현을 디자인 정본으로 삼지 않습니다.

같은 역할·상태·해상도·테마의 값을 비교합니다. 정적 선언만 확인했다면 화면 렌더 일치를 확인했다고 말하지 않습니다. 조건이 다르면 정규화 가능한 기준을 확인하거나 판단을 보류합니다. 페이지 고유의 강조, 의도된 배치와 역할별 변형은 근거가 있을 때만 예외로 제외합니다.

확정된 기준이 있으면 어느 페이지가 그 기준을 어겼는지 명시합니다. 두 페이지가 같은 잘못된 값을 쓰면 비교 결과와 별도로 그 사용 위반을 `component-usage`에 기록합니다. 같은 구현이 많다는 이유로 기준 위반을 숨기지 않습니다. 규칙이 없는 차이는 `review`이며 곧바로 불일치 분모에 넣지 않습니다.

## 계산

| 값 | 산식 |
| --- | --- |
| 전체 항목 `total` | 보고한 항목 수 |
| 적용 항목 `eligible` | 전체 − `not-applicable` |
| 판정 항목 `evaluated` | `match` + `mismatch` |
| 일치율 `matchRate` | `match` ÷ 판정 항목 × 100 |
| 검사 커버리지 `coverage` | 판정 항목 ÷ 적용 항목 × 100 |

비율은 소수점 둘째 자리까지 표시합니다. 분모가 0이면 `null`이며 0%나 100%로 대체하지 않습니다. `review`와 `not-measured`는 일치율 분모에서 제외하지만 적용 항목에는 남겨 커버리지에 반영합니다. `not-applicable`은 두 비율의 분모에서 제외하며 근거가 필요합니다.

예를 들어 일치 8, 불일치 2, 판단 필요 1, 미측정 2, 적용 제외 1이면 일치율은 `8/10 = 80%`, 커버리지는 `10/13 = 76.92%`입니다. 3개의 미판정 항목과 1개의 예외를 따로 표시합니다. 이 수치는 정해진 검사 항목의 결과이며 페이지 전체의 유사도나 품질 점수가 아닙니다.

## 문제 보고

컴포넌트 문제는 사용 위치·기대 컴포넌트와 사용법·관찰값·영향·근거를 남깁니다. 페이지 문제는 비교 페이지와 동등한 역할, 양쪽 위치·값, 기준 출처와 차이를 남깁니다. 이미지의 인상만으로 수치나 규칙 위반을 만들지 않습니다.

먼저 두 축의 일치율과 커버리지를 제시하고, 근거가 확인된 문제와 필요한 조치, 판단 필요·미측정·예외를 설명합니다. 비율이 높아도 중요한 사용 위반은 숨기지 않습니다. 임의 합격선으로 자동 PASS/FAIL을 만들지 않습니다.
