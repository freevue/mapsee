# 강제 색상 환경

일반 테마와 forced-colors 환경에서 정보·상태·경계·초점을 구별하고 조작할 수 있는지 확인합니다. 사용자 색상으로 바뀐 사실 자체를 프로젝트 색 토큰 위반으로 판정하지 않습니다.

## setup에서 확인할 기준

지원 환경과 기존 접근·키보드·상태 표시 계약을 찾습니다. 강제 색상 지원을 명시한 기준·예외가 있는지 확인하고, 없으면 실제 관찰과 필요한 채택 결정을 구분합니다. 검사를 추가하는 것과 새로운 표준 전체를 채택하는 것은 별개입니다.

그림자만으로 만든 포커스·경계, 배경색에만 의존한 선택 표시와 아이콘·SVG의 시스템 색 대응을 검토합니다. 모든 컴포넌트에 테두리를 추가하거나 forced-color-adjust:none을 공통 해결책으로 요구하지 않습니다. 원래 정보·조작과 사용자 설정을 유지하는 최소 제안을 남깁니다.

## lint 절차

1. 일반 환경과 강제 색상 환경의 실제 matchMedia 결과·브라우저·OS·재현 방법·뷰포트를 기록합니다. CSS 분기 선언만으로 환경이 적용됐다고 하지 않습니다.
2. 같은 대상·상태에서 포커스·선택·오류·버튼 경계·아이콘과 텍스트를 실제 화면과 계산된 스타일로 확인합니다. 그리기 단계 변경으로 작성자 값과 보이는 색이 다를 수 있으므로 원시 변수 값만으로 화면을 판정하지 않습니다.
3. 키보드로 초점을 옮기고 선택·실행·비활성 조작을 확인합니다. box-shadow 소실과 실제 초점 표시 소실은 관찰을 연결해 구분합니다. 대체 outline·경계·표시가 있으면 그것도 확인합니다.
4. 표시와 의미가 함께 유지되는지 [상태 검사](state-meaning.md)와 연결합니다. 일반 테마 대비 계산값이나 작은 이미지 하나로 강제 색상의 전체 접근성을 통과시키지 않습니다.

| 재현 | 보고 범위 |
| --- | --- |
| 실제 OS 설정 | OS·선택한 팔레트·브라우저와 실제 조작 조건으로 한정 |
| 브라우저 모의 | CDP·기존 도구의 설정과 실제 active 여부를 기록. 모의 결과이며 실제 Windows·전체 팔레트 수용이 아님 |
| 실행 불가 | 계획한 항목은 not-measured. 정적 스타일 대조만 수행한 사실을 별도로 보고 |

MDN은 [강제 색상에서 영향을 받는 속성](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/forced-colors)을 설명합니다. 예를 들어 box-shadow가 사라질 수 있으므로 선언 존재만으로 포커스 표시를 통과시키지 않습니다.

원본 계약에 적용되는 확정 위반은 mismatch, 지원·정책이 미정이면 관찰한 과업 영향과 함께 review입니다. 실제 OS를 실행하지 않았다는 이유로 브라우저 모의 관찰까지 삭제하지 않고 각 근거의 재현 수준을 유지합니다. 두 검사 축과 산식은 그대로 사용합니다.
