# 검사 결과 형식

Markdown과 JSON은 같은 검사와 근거를 표현합니다. JSON은 [가상 예시](report.example.json)의 구조를 사용합니다. bab·pstack 전용 필드는 없으며 받는 도구가 후속 작업을 선택합니다.

## 실행 정보

| 필드 | 내용 |
| --- | --- |
| `schemaVersion` | 이 형식은 `1`입니다. |
| `producer` | `mapsee`입니다. |
| `mode` | `report-only`입니다. |
| `runStatus` | `complete`, `incomplete`, `blocked` 중 하나입니다. |
| `scope` | 대상·표본 범위와 선택한 수집 방법입니다. `comparisons`에 비교 ID·대상·비교 페이지·선택 이유·공통 역할·상태·해상도·테마를 기록합니다. |
| `inputs` | 디자인 기준·코드·실행 서버·도구·환경의 식별 근거입니다. 확인할 수 없는 식별자는 `null`과 이유를 기록합니다. |
| `findings` | 각 검사 결과입니다. 불일치뿐 아니라 요청한 검사 중 미측정도 남깁니다. |
| `summary` | `componentUsage`와 `pageConsistency`의 항목 수·일치율·커버리지입니다. 집계 도구가 채웁니다. |
| `errors` | 실행을 막거나 일부 검사를 끝내지 못한 이유입니다. |

`complete`는 선택한 검사 범위의 확인을 끝냈다는 뜻입니다. 모든 화면·심미 품질·접근성의 수용을 뜻하지 않습니다. 불일치가 있어도 수집을 끝냈다면 `complete`일 수 있습니다. 기준 부재 등으로 시작할 수 없으면 `blocked`, 요청한 검사 일부를 하지 못했다면 `incomplete`입니다. 주관적 판단을 `review`로 남긴 것만으로 실행 오류가 되지는 않습니다.

## 항목별 정보

| 필드 | 내용 |
| --- | --- |
| `id` | 이 보고서에서 고유한 식별자입니다. |
| `axis` | 검사 목적은 `component-usage` 또는 `page-consistency`입니다. |
| `comparisonId` | 페이지 검사에서 `scope.comparisons`의 비교 ID를 가리킵니다. 컴포넌트 검사에는 필요하지 않습니다. |
| `kind` | 근거 수집 방법은 `static`, `measurement`, `review` 중 하나입니다. 검사 목적과 구분합니다. |
| `status` | 아래 판정 상태 중 하나입니다. |
| `criterion` | 기준 문서의 경로·문단과 적용 조건입니다. 기준이 없으면 `null`로 남깁니다. |
| `subject` | 코드 위치 또는 화면·요소·상태입니다. 코드 위치를 확인하지 못하면 추측으로 채우지 않습니다. |
| `expected` / `observed` | 기준과 실제 결과입니다. 알 수 없는 값은 `null`입니다. |
| `evidence` | 코드·명령 결과·DOM 측정·스크린샷·실제 조작 등 직접 확인한 근거와 출처입니다. 재사용 자료는 그 사실과 동일성 확인 범위를 적습니다. |
| `interpretation` | 관찰로부터 내린 해석입니다. 사실과 구분합니다. |
| `suggestion` | 최소 수정 제안 또는 필요한 결정입니다. 실행 명령이 아닙니다. |
| `confidence` | 근거의 확신을 `high`, `medium`, `low`로 적습니다. |
| `limitations` | 예외, 환경 차이와 확인하지 못한 부분입니다. |

경로는 대상 프로젝트 기준으로 식별하고 외부 자료는 출처를 명시합니다. 해시·기준 커밋·캡처 경로는 실제 확인한 값만 적습니다. 요청 범위와 무관한 식별값·비밀값·개인정보는 넣지 않습니다.

## 판정 상태

| 값 | 의미 |
| --- | --- |
| `match` | 명시한 기준과 확인한 대상이 일치합니다. |
| `mismatch` | 적용 조건이 확정된 기준과 구현의 불일치가 근거로 확인됐습니다. |
| `review` | 출처 충돌·모호한 기준·심미적 해석 등 추가 판단이 필요합니다. |
| `not-measured` | 자료·도구·상태·환경의 제한으로 해당 검사를 하지 못했습니다. 이유를 남깁니다. |
| `not-applicable` | 해당 기준의 적용 대상이 아니거나 문서화된 예외입니다. 범위와 근거를 남깁니다. |

`match`와 `mismatch`에는 기준 경로·문단, 기대값·관찰값과 근거 출처가 필요합니다. 페이지 검사에는 서로 다른 실제 대상·비교 페이지를 기록합니다. `not-applicable`에도 원본 기준과 예외 이유가 필요합니다. 화면 밖이라는 관찰만으로 의도된 스크롤을 불일치로 확정하지 않습니다.

## 비율 집계

두 축을 별도로 집계합니다. 각 요약은 `total`, `matched`, `mismatched`, `review`, `notMeasured`, `notApplicable`, `evaluated`, `eligible`, `matchRate`, `coverage`를 가집니다. [집계 규칙](comparison.md)의 산식과 제외 조건을 사용합니다. 판정 항목이 없으면 일치율은 `null`, 적용 항목이 없으면 커버리지도 `null`입니다.

설치된 lint 스킬의 경로에서 다음 명령을 실행합니다. 입력을 읽고 검증·집계한 전체 JSON을 표준 출력으로 내보내며 입력 파일을 수정하지 않습니다. 잘못된 상태·중복 ID·근거 없는 확정 판정·비교 대상 누락은 오류와 0이 아닌 종료 코드로 드러냅니다. 입력에 있던 수치 요약은 실제 항목으로 다시 계산합니다.

```text
node <lint 스킬 경로>/scripts/summarize.mjs <보고서.json>
```

이 도구는 입력 판정의 집계기입니다. 실제 컴포넌트 사용·페이지 비교의 판단과 근거 수집은 스킬을 수행하는 에이전트가 담당합니다.

## Markdown 보고

첫 문단에 검사 범위와 실행 상태를 적습니다. 컴포넌트 적합률과 페이지 일치율을 각각 `일치/판정 항목`, 검사 커버리지를 `판정/적용 항목`과 함께 보여줍니다. 예를 들어 `8/10 = 80%, 커버리지 10/13 = 76.92%, 판단 필요 1·미측정 2·예외 1`처럼 씁니다. 표본 결과임을 밝히고 실제 실행과 기록 재사용을 구분합니다.

문제에는 잘못 사용한 컴포넌트·변형·상태·스타일과 위치, 또는 비교 페이지의 같은 역할과 양쪽 차이·근거·제안을 적습니다. 높은 비율만 제시하고 개별 위반이나 미측정을 숨기지 않습니다. 기준 부재·충돌과 환경 실패도 별도로 설명합니다.

보고서 자체를 새 디자인 규칙으로 채택하거나 wiki에 복사하지 않습니다. 후속 도구는 원래 DESIGN 기준과 근거를 확인해 수정 범위와 필요한 문서 반영을 정합니다.
