# 모바일 키보드와 실제 표시 영역

화면 너비 표본과 실제 OS 키보드 검사를 구분합니다. 모바일 입력이 범위에 포함되면 키보드 전·중·후의 입력·오류·주요 행동 접근과 고정 UI를 확인합니다. 모든 화면에 모바일 지원이나 고정 하단 버튼을 강제하지 않습니다.

## setup에서 확인할 내용

지원 기기·브라우저와 입력 흐름, 키보드가 열렸을 때 유지할 요소·스크롤·고정 영역의 관계를 기존 가이드에서 찾습니다. 기기의 안전 영역·주소창·가로 전환·확대가 영향을 주는 경우 해당 조건을 추가합니다. 노치 대응이나 키보드 높이의 보편적인 고정값을 만들지 않습니다.

초점 입력과 오류를 볼 수 있고 필요한 행동에 도달할 수 있는지, 키보드를 닫은 뒤 값·초점·스크롤을 어떻게 복원하는지 원본 계약과 연결합니다. 가림이 관찰돼도 스크롤·키보드 닫기 등 허용된 접근 경로가 있는지 확인한 후 판단합니다.

## 실제 검사

1. 입력 전 layout viewport, visualViewport의 width·height·offset·scale, 스크롤 위치와 초점, 입력·오류·행동의 실제 경계를 기록합니다.
2. 실제 입력으로 OS 키보드를 열고 키보드 표시의 근거와 변경된 표시 영역을 기록합니다. focus 이벤트나 작은 innerHeight만으로 키보드가 열렸다고 판단하지 않습니다. virtualKeyboard API 사용 가능 여부와 OS 키보드의 실제 표시도 구분합니다.
3. 값을 입력하고 스크롤·다음 필드 이동·오류 확인·주요 행동 접근을 재현합니다. 겹침은 배치 경계뿐 아니라 실제 누르는 대상과 사용할 수 있는 경로를 함께 확인합니다. 제품 저장은 기존 격리 자료로 확인합니다.
4. 키보드를 닫고 값·초점·스크롤·고정 행동의 위치를 다시 수집합니다. 화면 회전·핀치·주소창 변화는 실제로 재현한 조건만 각각 보고합니다.

브라우저의 가시 영역은 키보드·핀치 등으로 달라질 수 있습니다. visualViewport 변화만으로 원인을 키보드라고 단정하지 않습니다. 관련 개념은 [MDN VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)를 참고합니다.

## 재현 수준과 보고

| 재현 수준 | 보고 원칙 |
| --- | --- |
| 실제 키보드 | 기기·OS·브라우저·입력과 키보드 표시 근거를 연결합니다. 해당 조건에서의 관찰로 한정합니다. |
| 합성 표시 영역 | 뷰포트 축소·CDP·테스트 오버레이 등의 방법과 바꾼 조건을 밝힙니다. UI 내구성 실험이며 실제 키보드 동작 통과가 아닙니다. |
| 표시 확인 불가 | 실제 OS 키보드를 열거나 확인할 수 없으면 계획한 키보드 항목은 not-measured로 남깁니다. 화면 너비·focus 검사로 대체 완료하지 않습니다. |

대상 조건은 inventory.binding과 evidence.context에 `inputMethod`·`viewportSource`·`visualViewport` 등 필요한 값으로 연결합니다. 실제 관찰값과 재현 방법을 같이 남기며 일치율을 높이기 위해 미측정을 지우지 않습니다. 두 검사 축과 산식은 유지합니다.
