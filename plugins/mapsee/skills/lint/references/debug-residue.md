# 검사용 문구·로그 잔여물

제품 페이지에 임시로 넣은 검사용 문구·표식·로그가 남아 있는지 검사합니다. 작성자가 AI인지 추측하지 않고, 확인한 용도·실행 경로·노출 조건으로 판정합니다. 확인된 잔여물은 심미적 개선 의견이 아닌 오류 `mismatch`로 보고합니다.

## 검사 범위와 근거

- **대상:** 검사할 페이지와 연결된 컴포넌트·문구·클라이언트 로그를 확인합니다. `검증용`·`테스트 통과`·`AI 확인용` 같은 임시 안내, 검사 ID·내부 상태·응답 객체를 보여주는 패널·배지·토스트, 임시 `console.log`·`console.debug`·`debugger` 등을 단서로 찾습니다. 단어·API의 존재만으로 오류를 확정하지 않습니다.
- **용도:** 제품 명세·기존 안내·로깅 정책과 소스의 주석·호출부·변경 근거를 대조합니다. 사용자 과업과 무관하게 검사 성공을 알리거나 검사자가 내부 상태를 보기 위해 넣은 잔여물인지 확인합니다. Git 변경 이력은 가능한 보조 근거이며 작성자 이름만으로 용도를 판단하지 않습니다.
- **노출:** 실제 화면·DOM·접근성 트리·콘솔에서 관찰한 위치와 재현 조건을 남깁니다. 소스에서는 해당 페이지로 이어지는 렌더·호출 경로, 개발/테스트 환경 조건과 배포 시 제외 여부를 확인합니다. 주석이나 문자열 검색 결과를 실행된 로그로 보고하지 않습니다. 이번 검사를 수행하는 도구가 출력한 로그도 제품 로그와 구분합니다.

## 판정

| 상황 | 판정 |
| --- | --- |
| 검사 목적으로 넣은 문구·패널·표식이 제품 화면이나 보조 기술에 노출됨 | `mismatch`. 이 문서의 잔여물 금지 기준과 실제 노출 근거를 연결합니다. |
| 임시 진단 로그·중단점이 제품 페이지의 실행 경로에 남고 의도한 진단 기능이나 개발 전용 경계가 없음 | `mismatch`. 소스 위치·용도·호출 경로·조건을 근거로 남깁니다. |
| 정상 사용자 안내·진행/오류 메시지, 정책에 맞는 운영 로그나 명시적으로 요청된 진단 기능 | 잔여물 오류로 잡지 않습니다. 내용·노출 정책에 별도 문제가 있으면 해당 기준으로 검사합니다. |
| 테스트 fixture·Storybook의 의도한 검사 표시, 확인된 개발 전용 진단, 동작을 바꾸지 않는 `data-testid` 등 테스트 선택자 | 제품 노출과 구분합니다. 테스트 전용 이름만 믿지 않고 실제 경계·사용 목적을 확인합니다. |
| 문구·로그의 용도나 실행 조건이 모호함 | `review`. 필요한 판단과 확인할 근거를 적습니다. |
| 계획한 화면·콘솔·조건을 확인하지 못함 | 해당 항목은 `not-measured`. 소스에서 확정한 잔여물과 실제 노출의 미측정을 구분합니다. |

## 보고와 검사 수행

개별 잔여물은 `component-usage`로 보고하며 별도 점수 축을 만들지 않습니다. `criterion`에는 이 문서의 판정 문단과 적용 조건을 연결합니다. 위치·문구 또는 로그의 종류·임시 용도·기대되는 부재·실제 관찰·실행 조건·영향과 최소 제거 제안을 기존 보고 필드에 기록합니다. 민감한 로그 값은 그대로 복사하지 않습니다. 같은 원인의 화면·소스·콘솔 근거는 한 문제로 묶습니다.

검사를 위해 제품 소스·화면 문구·DOM에 안내·배지·로그·중단점을 삽입하지 않습니다. 기존 화면과 읽기 전용 관찰을 사용하고, 별도 승인된 계측·합성 결과는 제품 원본과 구분합니다. 맵시 lint는 발견한 잔여물을 보고하며 직접 삭제하거나 정상 로그를 임의로 끄지 않습니다.
