# 상태와 조작 검사

종합 검사에서는 아래 다섯 주제 중 요청 범위에 해당하는 항목을 우선 계획합니다. 특정 컴포넌트만 요청받았다면 그 역할에 필요한 항목을 선택합니다. 체크리스트 전체나 외부 디자인 시스템의 취향을 모든 화면의 필수 규칙으로 만들지 않습니다.

## 적용 근거와 판정

각 항목에 적용 근거 → 재현 조건 → 기대 결과 → 관찰 → 판정 → 개선 제안을 연결합니다. 적용 근거는 프로젝트가 채택한 문서·공개 계약·표준의 해당 조항입니다. 표준은 버전·조항·등급·적용 예외와 채택 근거를 확인합니다. 휴리스틱은 검토 관점이며 단독으로 확정 위반을 만들지 않습니다.

직접 사용의 적합성은 `component-usage`, 동등한 역할·상태의 페이지 비교는 `page-consistency`로 보고합니다. 정적 선언과 실제 조작 결과를 구분하고 둘 다 확인했다면 같은 항목에 근거를 모읍니다. 재현하지 못한 상태는 삭제하거나 일치로 계산하지 않습니다.

폼 실패·권한·삭제 상태는 기존 프리뷰·테스트·분리된 가상 자료나 제공된 근거에서 확인합니다. 실제 제품 데이터의 저장·제출·삭제를 검사 권한으로 간주하지 않습니다. 안전하게 재현할 수 없는 요청 항목은 `not-measured`로 남깁니다.

## 상태별 완전성

- **조건:** 역할에 해당하는 기본·로딩·성공·오류·비활성·선택 상태, 첫 사용의 데이터 없음과 필터 결과 없음 등을 구분합니다. 모든 컴포넌트에 모든 상태가 필요한 것은 아닙니다.
- **확인:** 현재 상황을 알아볼 수 있는지, 사용 가능한 다음 행동이 있는지, 로딩 종료·재시도·상태 전환에서 설명과 행동이 어긋나지 않는지 확인합니다. 시각적 상태와 접근성 이름·상태 전달도 대조합니다.
- **근거:** 상태를 만드는 프리뷰·테스트 입력과 화면·DOM·조작 결과를 연결합니다. 상태 CSS가 있다는 사실만으로 그 상태의 표시나 전환을 통과시키지 않습니다. ARIA 선언·접근성 트리와 실제 보조 기술의 전달 결과도 구분하며, 속성 확인만으로 실제 음성 출력을 검증했다고 하지 않습니다.
- **출처:** [Carbon의 빈 상태 패턴](https://www.carbondesignsystem.com/building-blocks/core/patterns/empty-states), [WCAG 상태 메시지](https://www.w3.org/WAI/WCAG22/Understanding/status-messages).

## 입력 오류와 복구

- **조건:** 대상 입력의 잘못된 값·누락·제출 실패·수정 후 상태 중 확인 가능한 상황을 정합니다. 제출 결과는 기존 테스트나 프리뷰에서 재현합니다.
- **확인:** 유지되는 입력 이름·도움말·오류와 해당 필드의 연결, 문제와 수정 방법의 명확성, 오류 위치로의 이동과 초점, 수정·재시도 시 상태 복구를 확인합니다. 입력 보존이 확정된 요구라면 그것도 검사합니다.
- **근거:** label·오류 연결 선언과 실제 메시지·이동·수정 흐름을 구분합니다. 오류 요약을 쓰는 프로젝트는 요약과 필드 메시지·링크가 같은 오류를 가리키는지 확인합니다. 모든 서비스에 GOV.UK의 요약 형식과 문구를 강제하지 않습니다.
- **출처:** [GOV.UK 오류 요약](https://design-system.service.gov.uk/components/error-summary/), [WCAG 오류 식별](https://www.w3.org/WAI/WCAG22/Understanding/error-identification).

## 키보드·초점·레이어

- **조건:** Tab·Shift+Tab과 해당 패턴의 Enter·Space·방향키·Escape, 모달 열기·닫기, 고정 헤더·하단 영역이 있는 화면을 선택합니다.
- **확인:** 읽기·조작 순서와 초점의 관계, 현재 초점의 식별, 모달 진입·내부 이동·종료·복귀, 배경의 조작 차단 여부를 패턴과 대조합니다. 포털·중첩 레이어에서는 보이는 앞뒤 순서와 실제 입력 대상을 함께 확인합니다.
- **근거:** 접근성 역할·속성 선언, 실제 키 입력과 전후 초점, 가리는 요소와 화면 위치를 기록합니다. 화면 캡처만으로 초점 이동과 키보드 조작을 판정하지 않습니다.
- **예외:** WCAG 2.4.11 AA의 최소 기준은 저작자가 만든 내용에 초점 대상이 완전히 가려지지 않는 것입니다. 일부 가림과 완전 가림을 구분하고, 전혀 가리지 않는 더 엄격한 프로젝트 기준과 혼동하지 않습니다. APG 권장 패턴은 프로젝트의 역할·구현 계약과 함께 적용합니다.
- **출처:** [WAI-ARIA 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/), [WCAG 초점 가림 최소 기준](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum).

## 클릭·터치와 대체 조작

- **조건:** 닫기·아이콘 버튼·인접 행동, 작은 화면과 필요한 포인터 입력, 드래그가 있는 컴포넌트를 선택합니다.
- **확인:** 보이는 도형과 실제 반응 영역, 인접 대상 사이의 거리, 겹쳐서 다른 행동이 실행되는 부분을 확인합니다. 드래그 기능은 드래그 없는 단일 포인터 대안과 키보드 조작을 각각 확인합니다. 두 대안은 같은 검사가 아닙니다.
- **예외:** WCAG 2.5.8 AA를 채택한 경우 최소 `24×24 CSS px`와 간격·동등한 제어·인라인 등 조항의 예외를 함께 확인합니다. `44×44 CSS px`의 강화 기준이나 프로젝트 자체 목표를 AA의 일괄 최소값으로 쓰지 않습니다. 필수 드래그와 브라우저 자체 동작도 적용 범위를 구분합니다.
- **근거:** 실제 반응 영역과 간격, 입력 방법과 결과를 수집합니다. 아이콘 파일 크기만으로 누르는 영역을 판정하지 않습니다.
- **출처:** [WCAG 목표 크기 최소 기준](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum), [드래그 동작](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements).

## 확대와 반응형 내구성

- **조건:** 프로젝트의 주요 화면 크기와 전환점 주변, 채택한 확대·글자 크기·텍스트 간격 변경 조건을 명시합니다. 브라우저 확대와 글자만 확대하는 조건을 구분합니다.
- **확인:** 정보·행동의 누락, 겹침·잘림·스크롤, 정보·조작 순서, 오류·주요 행동의 접근성을 확인합니다. 화면이 작다는 이유만으로 정보를 제거해도 되는지 단정하지 않습니다.
- **예외:** WCAG 1.4.10 AA를 채택한 세로 스크롤 화면은 `320 CSS px` 상당의 폭에서 확인하며 의미상 2차원 배치가 필요한 표·지도 등의 예외를 구분합니다. 고정된 스크린샷 크기만으로 실제 확대나 텍스트 간격 변경까지 검사했다고 하지 않습니다. WCAG의 텍스트 간격 변경값은 기본 디자인값 강제가 아닌 변경 내구성 조건입니다.
- **근거:** 뷰포트·확대 방법과 비율·글자/간격 변경·스크롤 위치, 실제 표시와 사용 가능 여부를 기록합니다.
- **출처:** [WCAG 리플로](https://www.w3.org/WAI/WCAG22/Understanding/reflow), [글자 확대](https://www.w3.org/WAI/WCAG22/Understanding/resize-text), [텍스트 간격](https://www.w3.org/WAI/WCAG22/Understanding/text-spacing).
