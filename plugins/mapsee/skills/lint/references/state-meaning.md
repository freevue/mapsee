# 표시와 실제 선택 상태

표시된 선택, 실제 값·활성 콘텐츠, 공개된 의미·상태와 키보드 조작이 같은 상태를 가리키는지 확인합니다. ARIA 속성 하나나 색 하나만으로 상태 전체를 통과시키지 않습니다.

## setup에서 확인할 기준

기존 컴포넌트 계약에서 선택의 소유자·기본값·허용 개수·활성 콘텐츠·전환 시점과 입력 방식을 찾습니다. native radio/checkbox·토글 버튼·탭을 구분합니다. 각 패턴의 checked·aria-pressed·aria-selected를 서로 바꿔 적용하지 않습니다.

탭의 자동 활성화와 수동 활성화, 선택과 초점의 관계를 원본 기준으로 확인합니다. 방향키로 초점만 옮기는 수동 탭을 선택 불일치로 오판하지 않습니다. 탭처럼 보이는 화면 이동 링크에 tab 역할을 강제하지 않습니다.

## lint 절차

1. 실제 공용 컴포넌트·호출부·상태 값을 따라 역할과 상태 소유자를 확인합니다. 같은 문자열·className·ID 표식만으로 해당 패턴 사용을 인정하지 않습니다.
2. 조작 전후의 표시·DOM 값·상태 속성·초점·연결한 콘텐츠의 visible/hidden을 함께 수집합니다. native 입력은 실제 checked·disabled와 폼 값을 읽고 ARIA 선언만으로 대체하지 않습니다.
3. 지원하는 포인터·키보드 조작을 재현합니다. 탭·라디오의 선택 개수, 연결한 패널·라벨 ID, 비활성 선택의 진입·실행 여부를 적용 계약과 대조합니다. 비활성 표현만 있고 동작이 실행되는 경우도 확인합니다.
4. 색과 상태가 함께 바뀌어도 실제 내용·값이 이전 상태인지 확인합니다. 페이지마다 같은 역할이 다른 상태를 가리키는 문제와 의도된 패턴 차이를 구분합니다.

예를 들어 새 탭 색과 새 패널은 표시됐는데 aria-selected가 이전 탭에 남으면 해당 상태의 불일치입니다. 반대로 native 라디오가 정상적으로 checked를 전달한다면 aria-selected 부재를 위반으로 만들지 않습니다.

소스·실제 조작·DOM/접근성 트리 관찰·이미지 해석을 각각 연결합니다. 선언과 트리 확인으로 실제 화면 읽기 프로그램의 음성 출력을 검증했다고 하지 않습니다. 단계별 결과는 [연속 상태 전환](transitions.md), 정지 비교는 [캡처 준비](capture.md)를 따릅니다.

[W3C 탭 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)은 역할·연결·조작을 확인하는 원본 참고입니다. 패턴의 선택 사항과 프로젝트가 채택한 계약을 구분하고 다른 패턴에 그대로 복사하지 않습니다.
