# 결과 이력 비교

이전 결과를 지정받거나 버전별 재검사를 요청받았을 때 사용합니다. 같은 프로젝트의 보고서인지, 원본 기준·계약·코드·수집 조건과 이번 검사 범위를 먼저 확인합니다. 지정한 자료가 없으면 비교 기준 없음으로 보고하고 임의의 과거 파일을 정답으로 선택하지 않습니다.

같은 역할·규칙·상태를 다시 검사할 때 검사 ID를 유지합니다. 버전이나 실행일만 바뀌었다는 이유로 ID를 바꾸지 않습니다. 역할이 달라졌으면 별도 ID와 이유를 남기고 이전 항목의 누락을 해결로 해석하지 않습니다.

## 비교 입력

기존 report schemaVersion 1을 사용합니다. `subject.path`·role·conditions, criterion의 경로·문단·조건, expected, kind와 비교 페이지의 쌍을 연결합니다. 측정 조건은 항목별 `subject.conditions`, 페이지 비교의 conditions, 공통 `scope.conditions` 순서로 찾습니다. 조건 근거가 없으면 비교 불가로 남깁니다.

변경을 추적해야 하는 원본에는 criterion.digest 등 확인한 식별 근거를 기록할 수 있습니다. 집계 도구는 기준 문서의 숨은 변경이나 보고서 근거의 진위를 자동 판별하지 않습니다. 서로 다른 조건을 같은 것으로 기록해 해결 판정을 만들지 않습니다.

```text
node <lint 스킬 경로>/scripts/compare.mjs <이전보고서.json> <현재보고서.json>
```

이 명령은 두 입력을 읽고 비교 JSON을 출력합니다. 파일·기준 화면·제품 코드를 수정하지 않습니다. 불일치가 남아 있어도 정상 비교는 종료 코드 0이며, 입력·형식 오류는 종료 코드 1입니다.

## 출력 분류

| category | 의미 |
| --- | --- |
| new-problem | 새 검사 또는 비교 가능한 기존 검사에서 이번에 불일치로 확인. 새 코드가 원인인 회귀라는 뜻은 아님 |
| resolved | 같은 기준·대상·방법·조건의 불일치를 다시 확인해 일치로 판정 |
| remaining-problem | 비교 가능한 항목이 계속 불일치 |
| not-rechecked | 이번 보고서에서 빠졌거나 미측정. 해결로 세지 않음 |
| changed-basis | 기준·기대값·대상·방법·조건·비교 쌍이 바뀌거나 조건 근거가 없음 |
| added-check | 이전에 없던 검사이며 이번 판정은 불일치가 아님 |
| unchanged | 비교 가능한 항목의 판정 상태가 같음. 관찰 내용까지 같다는 뜻은 아님 |
| changed-status | 검토·예외 등 다른 상태로 변경. 해결과 구분 |

페이지·항목·수집 조건이 다르면 두 보고서의 일치율 증감으로 개선을 주장하지 않습니다. 기준 변경·범위 제외·미측정은 근거와 함께 보고합니다. 도구 출력은 새로운 디자인 규칙이나 수정 승인으로 사용하지 않습니다.
