# 툴팁·메뉴의 연결·가림·유지

트리거에 연결된 툴팁·드롭다운·비모달 팝오버가 대상이면 이 문서를 읽습니다. 모달 Dialog와 브라우저 native title은 다른 패턴입니다. name·role·CSS 클래스만으로 같은 사용 계약을 적용하지 않습니다.

## setup에서 확인할 내용

기존 가이드에서 트리거와 내용의 역할·이름·연결, 열기·선택·닫기·초점 복귀, 스크롤·확대·작은 영역에서의 위치와 충돌 회피 정책을 찾습니다. tooltip 안에 조작이 필요한지, 메뉴·팝오버가 더 맞는 역할인지 원본 패턴과 실제 과업으로 확인합니다. 특정 위치·거리·라이브러리를 일괄 강제하지 않습니다.

## 검사 절차

1. 트리거·내용·포털 목적지·스크롤 조상을 실제 요소로 식별합니다. aria-controls·aria-describedby 등의 연결과 해당 내용의 이름·역할을 공개 계약에 비춰 확인합니다. 속성이 있다는 이유만으로 동작을 통과시키지 않습니다.
2. 포인터·키보드의 지원 입력으로 열고 양쪽 경계와 좌표계를 기록합니다. 스크롤·리사이즈·확대 전후에 트리거와의 관계, 화면 가장자리·overflow 잘림·레이어 가림을 확인합니다. 위치 전환·flip·shift가 허용되면 단순 좌표 차이를 위반으로 만들지 않습니다.
3. 실제 화면에서 내용과 선택지에 도달하는지, 다른 레이어가 입력을 받는지 확인합니다. 단순 z-index 크기나 스크린샷으로 실제 누르는 대상을 확정하지 않습니다. 강제 클릭으로 가림을 우회하지 않습니다.
4. 호버로 나타나는 내용은 트리거에서 내용으로 포인터를 옮겼을 때 필요한 내용이 유지되는지 확인합니다. 키보드 초점·Escape·바깥 클릭·선택 후 닫기의 적용 여부와 결과는 해당 패턴의 계약으로 검사합니다. 모든 tooltip에 메뉴의 방향키·초점 이동을 강제하지 않습니다.

WCAG 2.2의 1.4.13 AA를 채택했다면 적용 대상과 dismissible·hoverable·persistent, 입력 오류·의미 있는 내용을 가리지 않는 경우·사용자 에이전트 표현의 예외를 함께 확인합니다. [W3C 해설](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html)을 연결하고 미채택 휴리스틱은 review로 남깁니다.

## 근거와 한계

조작 순서·트리거/내용 식별자·URL·상태·뷰포트·스크롤·확대·양쪽 경계·입력 대상·닫기/초점 결과를 필요한 만큼 연결합니다. 정지 비교는 [캡처 준비 상태](capture.md), 과정 확인은 [연속 상태 전환](transitions.md)을 따릅니다.

실제 대상이 없으면 탐색 범위와 패턴 부재를 보고합니다. 브라우저 title을 커스텀 tooltip으로 둔갑시키지 않습니다. 합성 화면에서 확인한 유지·위반 사례는 도구 검증 자료이며 제품 사용처의 통과가 아닙니다. 계획한 제품 사용처를 실행하지 못하면 not-measured입니다.
