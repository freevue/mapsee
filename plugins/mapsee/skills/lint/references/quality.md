# 근거 연결·문제 분류·재검사 제안

보고서의 연결 정보와 원본을 대조합니다. 집계 도구는 기록의 정합성을 확인하며, 화면·소스의 진위를 자동 입증하지 않습니다. 기존 두 검사 축과 적합률은 유지합니다.

## 강화된 대상 연결

새로 수집하는 보고서는 `scope.bindingVersion: 1`을 사용합니다. 기존 inventory 행에 binding을 연결하고 판정·근거에서도 같은 대상 ID를 참조합니다. 이전 보고서는 그대로 읽되 강화 검증을 통과했다고 표시하지 않습니다.

| 위치 | 연결 정보 |
| --- | --- |
| inventory[].binding | url 또는 sourcePath. 사용처에는 selector 또는 sourcePath, 상태 대상에는 state를 적습니다. 실제 재현할 viewport·theme·콘텐츠 조건도 관련될 때 포함합니다. |
| finding.subject.targetIds | 이 판정이 확인하는 inventory 대상 ID 배열 |
| finding.criterion.digest | 읽은 원본 기준의 식별자. 가능하면 원본 파일·선택한 계약의 내용 해시를 사용합니다. |
| finding.evidence[] | targetId, captureId, source, basisDigest, context를 연결합니다. basisDigest는 해당 판정의 criterion.digest입니다. |
| evidence.context | 원시 수집에서 확인한 url·sourcePath·selector·state·viewport 등의 조건. 계획값을 관찰값으로 복사하지 않습니다. |

URL은 비교 목적에 맞게 pathname·query를 기록하고 실행 서버 출처는 별도로 보존합니다. selector는 실제 대상을 식별하는 표현입니다. DOM 근거는 해당 요소·상태를 확인한 수집 기록에, 코드 근거는 확인한 소스 위치와 파일 식별에 연결합니다. 페이지의 공통 조사와 특정 상태의 재현을 구분합니다.

수집 ID는 저장한 DOM·조작 JSON·스크린샷 등 원본에서 다시 찾을 수 있어야 합니다. 같은 판정이 여러 대상·상태를 확인하면 대상마다 올바른 근거를 연결합니다. 비교 페이지 양쪽도 각각 확인합니다. 하나의 사진·기본 상태로 처리 중·오류까지 완료로 만들지 않습니다.

집계기는 대상의 binding이 근거 context와 일치하는지, 대상 ID와 기준 식별자가 연결되는지 확인합니다. 강화 모드의 inventorySummary.bindingIssues에 차이를 남기고 해당 대상은 pending입니다. 미검사 대상이 있는 complete는 거부합니다. 집계기의 연결 검사와 [근거 원본 묶음 검사](evidence.md)를 구분합니다. 원본을 인계할 때 파일 해시·JSON Pointer·기준과의 연결도 대조하고 결과를 함께 남깁니다. 이미지 내용·수집자의 진위는 수행자가 별도로 검토합니다.

연결이 틀리면 원본을 보존하고 실제 올바른 근거로 교정하거나 해당 범위를 미측정으로 남깁니다. 집계 통과를 위해 관찰 조건·ID를 계획값에 맞춰 다시 쓰지 않습니다.

## 문제 분류

문제 정리를 요청받거나 종합 검사할 때 `scope.triageVersion: 1`을 사용합니다. 불일치·검토 항목에만 issue를 적습니다. 확인하지 못한 실행 환경과 단순 미측정은 제품 문제로 만들지 않습니다.

issue의 groupId·cause·ownerPath는 같은 원인과 소유 위치를 식별합니다. impact는 아래 값, reason은 실제 과업에 미친 영향과 근거입니다. 같은 외형이라는 이유로 다른 원인을 묶지 않습니다. 원인을 모르거나 독립 문제면 별도 그룹과 확인할 사항을 남깁니다.

| impact | 의미 |
| --- | --- |
| blocking | 요청 과업을 완료하지 못하고 확인한 대안도 없음 |
| degraded | 과업은 가능하지만 우회·불필요한 조작·정보 접근 어려움이 발생 |
| presentation | 확인한 영향이 시각적 표현 차이에 한정됨 |
| undetermined | 과업 영향의 판단 근거가 부족함 |

영향도는 확정 위반 여부와 별개입니다. review도 실제 조작 문제를 관찰할 수 있지만 그 사실만으로 프로젝트 규칙을 새로 만들지 않습니다. 단순 여백 차이에 차단 등급을 붙이거나 임의 종합 점수를 만들지 않습니다.

problemSummary는 원인 그룹·판정 수·위치·개별 영향 근거를 묶습니다. 분류하지 못한 항목은 untriaged로 남깁니다. 같은 그룹의 원인·소유 위치가 충돌하면 오류입니다. 한 원인이 여러 위치에 미친 경우 지적 수와 영향 위치 수를 구분합니다. 그룹의 가장 높은 관찰 영향과 영향 미정이 함께 있으면 둘 다 표시합니다.

## 변경 영향과 재검사 제안

실제 변경 파일 또는 사용자가 지정한 가상 시나리오를 구분합니다. 공용 구현·스타일·공개 export·앱 래퍼에서 실제 사용처·페이지·상태까지 호출 경로를 따라가고 원본 근거를 남깁니다. 검색 문자열만으로 동적 사용과 전체 영향 범위를 보증하지 않습니다.

scope.dependencies는 path·targetIds·evidence 배열입니다. path는 변경과 대조할 프로젝트 상대 파일 경로, targetIds는 실제 영향이 확인된 inventory 대상, evidence는 호출·재내보내기·스타일 연결의 원본 위치입니다. 중간 경로도 각 파일에 연결합니다. 이 표는 보고서의 파생 자료이며 별도 프로젝트 정본이나 wiki를 만들지 않습니다.

```text
node <lint 스킬 경로>/scripts/retest.mjs <보고서.json> <변경파일문자열배열.json>
```

도구는 확인한 관계와 변경 파일을 대조해 selected·unmappedChanges·outOfScopeAffected를 출력합니다. 입력을 수정하지 않으며 실행·제품 수정·기존 필수 검사 축소를 승인하지 않습니다. 변경 0개와 영향 미상은 구분합니다. 선택 0개를 검사 불필요로 해석하지 않습니다. 전역 스타일·자료 부족·이름 변경·미연결 경로는 수동 검토와 범위 확대 후보입니다.
