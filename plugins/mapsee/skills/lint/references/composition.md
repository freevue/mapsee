# 간격·중첩·배치·선택 이유

setup·document는 아래 관계가 프로젝트 문서에 설명되어 있는지 확인하고 필요한 범위를 보완합니다. lint는 그 문서와 실제 사용을 대조합니다. 여기의 수치와 관계식은 설명용 후보이며 프로젝트가 채택한 기준·적용 조건·예외를 우선합니다.

## 문서에 남길 내용

각 기준에 적용 화면·컴포넌트·역할·상태, 근거와 결정 상태, 참조 토큰, 값 또는 관계식, 반응형 조건·허용 오차·예외, 대표 사용 예와 확인 방법을 적습니다. 관계를 설명하는 데 필요한 항목만 사용하고 같은 기준은 정본으로 연결합니다.

| 주제 | 확인하고 정리할 관계 |
| --- | --- |
| 간격과 여백 | 같은 역할의 내부 padding·요소 간 gap·그룹 사이 여백, 정보 위계에 따른 간격 단계와 화면 크기별 변화 |
| 중첩 라운드 | 부모와 자식의 표면 경계, 각 모서리의 반경·실제 안쪽 거리, 안쪽 반경을 결정하는 관계와 예외 |
| 배치 정합성 | 컴포넌트가 속한 정보 그룹과 위치, 읽기·조작 순서, 관련 설명·오류·행동의 연결과 반응형 재배치 |
| 선택 이유의 정합성 | 사용자가 하려는 일과 화면 목적, 정보량·행동·상태·제약에 맞는 컴포넌트 역할, 선택 근거와 다른 선택이 허용되는 조건 |

## 간격과 여백의 통일성

- 같은 역할·밀도·상태의 간격이 같은 토큰 또는 채택된 관계를 따르는지 확인합니다. 모든 간격을 같은 숫자로 만들지 않고 요소 내부·같은 그룹·그룹 사이의 위계를 구분합니다.
- padding·margin·gap 선언뿐 아니라 실제 경계 사이의 거리를 확인합니다. margin 겹침·줄바꿈·숨겨진 요소·반응형 전환으로 달라질 수 있으므로 선언값만으로 실제 여백을 확정하지 않습니다.
- 프로젝트의 간격 단계와 좁은 화면 변환이 문서에 있는지 확인합니다. 없으면 실제 사용을 관찰로 정리하고 채택할 기준을 묻습니다. 보편적인 간격 배수나 허용 오차를 임의로 추가하지 않습니다.

## 중첩된 표면의 라운드

부모 카드 안에서 여백을 두고 작아지는 자식 표면은 부모와 같은 반경을 복사했는지만 보지 않고 두 곡선과 여백의 관계를 봅니다. 이 중첩 표면 관계를 채택한 프로젝트에서는 안쪽 반경을 줄여 일정한 곡선 간격을 유지하는 기준을 문서화합니다.

균일한 안쪽 거리와 원형 모서리를 가진 평행한 두 경계라면 후보 관계는 `innerRadius = max(0, outerRadius - inset)`입니다. `inset`은 부모의 바깥 경계부터 자식의 바깥 경계까지의 거리로, 부모 border·padding과 추가 오프셋을 포함해 확인합니다. 같은 단위로 비교하며 border를 빠뜨리거나 두 번 더하지 않습니다.

예를 들어 바깥 반경이 `24px`, 실제 안쪽 거리가 `8px`라면 후보 안쪽 반경은 `16px`입니다. 안쪽 거리가 `12px`로 바뀌면 후보는 `12px`입니다. 프로젝트가 이 관계를 채택했다면 자식 값의 고정 숫자뿐 아니라 참조 토큰·계산 관계가 여백 변경에 맞춰 유지되는지도 확인합니다. 문서 보완은 이 의존 관계를 설명하며 제품 CSS를 자동으로 바꾸지 않습니다.

이 후보는 [W3C의 같은 상자 내부 경계 반경 정의](https://www.w3.org/TR/css-backgrounds-3/#corner-shaping)를 별도의 중첩 표면에 응용한 설계 제안입니다. CSS가 자식의 반경을 자동 계산한다는 뜻은 아닙니다. 큰 반경은 상자 크기에 따라 실제 사용값이 줄어들 수 있으므로 [곡선 겹침 처리](https://www.w3.org/TR/css-backgrounds-3/#corner-overlap)도 고려합니다.

- 같은 곡선 관계를 유지해야 하는 배경 표면인지 먼저 확인합니다. 부모 카드 안의 독립적인 pill 버튼·원형 아바타에 일괄 적용하지 않습니다.
- 비대칭 여백·모서리별 반경·타원·백분율·변환·잘림은 실제 경계와 사용된 모양을 확인합니다. 단일 inset을 추측해 계산하지 않고 프로젝트의 보정·예외가 없으면 `review`로 남깁니다.
- 선언값만 확인했다면 관계식의 선언 준수와 실제 시각적 자연스러움을 구분합니다. 실제 화면이 필요한 항목은 확인하지 못했을 때 `not-measured`로 남깁니다.

## 컴포넌트 배치와 선택 이유

- **배치:** 문서화된 그룹·위계·행동 흐름에 맞는 위치와 순서인지 확인합니다. 설명과 대상 입력, 오류와 해당 필드, 주요 행동과 영향을 받는 영역의 연결을 살핍니다. 시각 순서와 DOM·포커스 순서가 다른 경우 각각 근거를 수집합니다.
- **선택 이유:** 화면 목적·사용자 과업·공개 역할·사용 가이드와 실제 컴포넌트의 의미·행동·상태·정보량을 대조합니다. API가 허용하는 props를 썼거나 같은 컴포넌트를 재사용했다는 사실만으로 선택이 적절하다고 판정하지 않습니다.
- 사용 이유가 별도 문장으로 없더라도 화면 명세와 사용 가이드에서 역할을 확인할 수 있으면 그 근거를 연결합니다. 작성자의 의도나 사용자의 선호를 추측하지 않습니다. 설명 누락만으로 잘못된 컴포넌트라고 단정하지 않고 문서 보완 후보와 선택의 위반을 구분합니다.
- 다른 컴포넌트를 제안한다면 어떤 요구와 현재 선택이 충돌하는지, 제안이 그 요구를 어떻게 충족하는지 적습니다. 규칙이 없거나 두 선택 모두 가능한 경우 `review`로 남기고 결정할 사항을 밝힙니다.

## 검사 항목과 보고

요청 범위에 해당하는 간격·중첩·배치·선택 이유를 검사 전에 항목으로 정합니다. 직접 사용의 적합성은 `component-usage`, 동등한 역할의 페이지 간 관계 비교는 `page-consistency`에 넣습니다. 별도 취향 점수나 세 번째 검사 축을 만들지 않습니다.

부모·자식과 관련 요소의 위치, 목적·기대 관계, 관찰한 값·배치·역할, 원본 기준과 근거, 영향·최소 제안·미검증을 기존 보고 필드에 남깁니다. 같은 기준의 간격과 라운드 문제가 하나의 원인이라면 영향은 모두 설명하되 같은 지적을 중복 집계하지 않습니다.

| 상황 | 판정 원칙 |
| --- | --- |
| 채택된 중첩 기준이 바깥 `24px`·안쪽 거리 `8px`에서 안쪽 `16px`를 요구하지만 선언은 `24px` | 적용 조건과 선언 근거가 있으면 사용 불일치입니다. 실제 모양은 별도 확인합니다. |
| 두 화면이 각각 `24/8/16px`, `32/8/24px`이고 같은 중첩 관계를 채택한 조건 | 원시 반경 숫자가 달라도 해당 관계는 일치합니다. 그 결과를 색·배치 등 다른 항목의 일치로 확대하지 않습니다. |
| 카드 안의 pill 버튼이 부모보다 큰 라운드를 사용 | 독립적인 모양의 역할·예외를 확인합니다. 중첩 카드 반경 공식만으로 위반으로 만들지 않습니다. |
| 확정된 화면 흐름은 필드 옆 오류를 요구하지만 오류가 다른 그룹에 배치됨 | 그룹·위치와 기준이 확인되면 배치 불일치입니다. 배치 순서와 실제 가림·조작은 구분합니다. |
| 컴포넌트 선택 이유가 문서에 없고 기존 역할 근거도 불충분함 | `review`와 문서 보완 제안을 남깁니다. 코드에서 임의의 이유를 만들어 일치로 처리하지 않습니다. |
| 정적 배치는 확인했지만 좁은 화면의 실제 간격·순서·초점을 확인하지 못함 | 확인한 정적 항목과 `not-measured`인 화면 항목을 구분합니다. |
