# 배치 영역에 따른 사용 적합성

화면 너비와 컴포넌트가 놓인 실제 영역의 너비를 구분합니다. 넓은 화면의 좁은 모달·카드·사이드바도 검사 후보입니다. CSS container query 채택이나 특정 크기·밀도를 요구하는 규칙은 아닙니다.

## setup에서 확인할 기준

기존 DESIGN·사용 가이드에서 역할, 부모 영역, 콘텐츠 양, 허용한 크기·variant·배치와 전환 조건을 연결합니다. 좁은 영역에서 유지해야 할 이름·설명·오류·행동과 줄바꿈·스크롤·재배치의 허용 범위도 필요한 만큼 설명합니다.

예를 들어 같은 주요 행동이라도 모달과 본문에서 다른 크기를 허용할 수 있습니다. 해당 차이의 역할·조건·원본 근거가 있으면 보존합니다. 코드에서 발견한 축소값을 새 규칙으로 정하거나 좁은 곳에서는 항상 작은 variant를 쓰도록 강제하지 않습니다. 기준 부재는 관찰·미결정으로 남깁니다.

별도 문서나 전 컴포넌트의 크기표를 의무화하지 않습니다. 기존 가이드의 해당 항목을 보완하며 공개 props 계약은 원본으로 연결합니다. 같은 입력·결정으로 재실행하면 설명과 결정 상태를 중복 추가하거나 바꾸지 않습니다.

## lint에서 확인할 내용

1. 실제 사용처의 역할과 부모를 찾습니다. 기준이 컴포넌트 자체·부모의 content box·변환 후 보이는 영역 중 어디에 적용되는지 확인합니다.
2. 가능하면 같은 뷰포트에서 넓고 좁은 실제 사용처를 선택합니다. 뷰포트·부모 경계·content box·padding·gap·변환을 구분해 수집합니다. 부모 크기만 바꾸는 브라우저 실험은 합성 조건으로 표시합니다.
3. 사용한 공용 컴포넌트·size·variant·확장 스타일을 원본 기준과 대조합니다. 줄바꿈·최소 너비·축소·overflow와 실제 정보·오류·행동 접근을 확인합니다. 선언된 max-width를 측정된 실제 너비로 대신하지 않습니다.
4. 같은 영역의 같은 역할·상태를 페이지 간 비교합니다. 부모 영역·밀도·역할이 다른 차이는 적용 조건을 확인한 뒤 허용 차이 또는 review로 남깁니다. 원시 크기가 같다는 이유만으로 적합성을 보증하지 않습니다.

직접 사용은 component-usage, 동등 역할의 페이지 비교는 page-consistency입니다. 기존 두 축과 산식을 유지합니다. 크기가 다르다는 사실만으로 mismatch를 만들지 않습니다. 확정 기준이 없으면 review, 계획한 실제 영역을 확인하지 못하면 not-measured입니다.

## 재현 정보

강화 연결의 inventory.binding과 evidence.context에 관련되는 경우 아래 정보를 추가합니다. 실제 관찰에서 값을 얻으며 계획값을 복사하지 않습니다.

```json
{
  "url": "/settings",
  "selector": "#save",
  "state": "default",
  "viewport": { "width": 1440, "height": 1000 },
  "container": { "selector": ".settings-panel", "width": 360, "contentWidth": 312 }
}
```

수치는 가상 예시입니다. 컨테이너는 선언이 아닌 실제 요소로 식별합니다. 변환·스크롤의 영향을 별도로 남기고 모든 너비·부모 조합을 검사했다고 하지 않습니다. 대상 조건과 다른 부모 크기의 근거는 해당 항목의 완료 근거가 아닙니다.

화면 크기와 컨테이너 크기의 구분은 [MDN 설명](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries)을 참고합니다. 특정 CSS 기능의 사용 여부를 디자인 적합성으로 판정하지 않습니다.
