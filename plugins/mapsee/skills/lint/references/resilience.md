# 콘텐츠·환경 변화와 검사 재현성

이 문서는 연속된 의미 중복을 검사하거나, 요청 범위에 모바일·반응형 줄바꿈·긴 콘텐츠·테마·움직임·로딩 안정성·정보와 행동의 명확성이 포함되거나, 화면 비교를 재현할 때 읽습니다. [상태와 조작 검사](interaction.md)의 근거·판정 원칙을 함께 적용합니다.

## 콘텐츠 길이와 언어

- **조건:** 짧은·긴 제목과 버튼 이름, 긴 사용자 입력·URL·숫자, 지원하는 언어의 번역문 등 대상 역할에 맞는 자료를 선택합니다. 오른쪽에서 왼쪽으로 쓰는 언어를 지원한다면 그 방향과 혼합 문자열도 확인합니다.
- **확인:** 줄바꿈·말줄임·정보 접근 경로, 가변 높이의 정렬, 제목과 주요 행동의 위계, 카드·탭·입력의 넘침을 확인합니다. 모든 문자열에 동일한 줄바꿈·말줄임 규칙을 강제하지 않습니다.
- **판정:** 문서화된 길이·표시·방향 조건과 실제 화면을 대조합니다. 번역 시 글자 수가 일정 배수로 늘어난다고 단정하지 않고 원본 또는 가상 자료의 출처를 밝힙니다.
- **출처:** [W3C 번역과 문자열 길이](https://www.w3.org/International/articles/article-text-size), [텍스트 방향 안내](https://www.w3.org/International/questions/qa-html-dir).

## 모바일·반응형의 불필요한 줄바꿈

- **조건:** 제목·탭·버튼·라벨·상태 배지·설명 중 대상 요소를 정합니다. 지원하는 좁은 화면과 실제 부모 영역, 확인한 레이아웃 전환점 전후를 같은 콘텐츠로 비교합니다. 글꼴 로딩·언어·확대·텍스트 크기와 부모의 실제 사용 가능 너비를 기록합니다.
- **확인:** 짧은 이름이 글자 단위로 쪼개지거나 조사·문장부호·짧은 마지막 단어만 별도 줄에 남는지, 아이콘과 문구가 갈라지는지, 동등한 탭·버튼의 줄 수 차이가 높이·정렬·위계를 해치는지 확인합니다. 발견한 사례는 줄별 텍스트와 높이·주변 정렬을 화면 근거로 남깁니다.
- **원인과 제안:** 고정 너비·과한 여백·강제 `br`·`white-space`·`word-break`·`overflow-wrap`·flex/grid 축소 조건을 실제 계산값과 연결합니다. 확인한 원인에 맞춰 너비·배치·문구·줄바꿈 정책의 최소 변경을 제안합니다. 모든 텍스트에 `nowrap`·말줄임·고정 높이를 강제하거나 글자 크기 축소·콘텐츠 삭제로 문제를 숨기지 않습니다.
- **판정:** 여러 줄이라는 사실만으로 위반을 만들지 않습니다. 긴 번역·확대에 필요한 자연스러운 줄바꿈과 의도한 제목 구성을 구분합니다. 확정된 표시 계약 위반은 `mismatch`, 읽기 흐름·시각적 균형에 관한 개선 의견은 근거와 함께 `review`로 남깁니다. 실제 렌더를 보지 못하면 해당 화면 항목은 `not-measured`이며 CSS 선언만으로 통과시키지 않습니다.

## 연속된 의미 중복

- **조건:** 같은 상태에서 동시에 보이고 읽기 순서상 이어지는 탭·페이지 제목·섹션 제목·설명·상태·버튼을 비교합니다. 문자열이 달라도 같은 의미만 반복하는지 확인하며, DOM에 공존하지만 반응형 조건으로 한쪽이 숨겨진 요소는 시각적 중복으로 세지 않습니다.
- **확인:** 각 표현이 새 정보·범위·행동·현재 위치의 단서를 추가하는지 확인합니다. 예를 들어 선택된 `활동` 탭 바로 아래 제목이 다시 `활동`이고 별도 맥락을 주지 않으면 중복 후보입니다. 제목 뒤 설명의 단순 재진술, 같은 상태를 연속된 배지·문구로 반복하거나 같은 행동을 인접 버튼으로 반복하는 경우도 살핍니다.
- **예외:** 제목이 독립적인 섹션 구조·목차·보조 기술 탐색에 필요하거나, 좁은 화면에서 탭이 숨겨져 제목이 현재 위치를 알려주는 경우는 역할을 확인합니다. 긴 페이지의 멀리 떨어진 행동 재제공, 상태를 색 외의 문구로 알리는 표현, 아이콘과 이름의 조합은 같은 의미라는 이유만으로 제거 대상으로 삼지 않습니다.
- **판정과 제안:** 반복되는 양쪽 위치·실제 문구·역할·동시 표시 조건과 추가 정보의 유무, 차지하는 공간과 읽기 흐름의 영향을 함께 보고합니다. 확정된 중복 방지 기준이나 사용자가 지정한 적용 조건의 위반은 `mismatch`, 역할이 불명확하거나 사용성 해석에 그치는 경우는 `review`입니다. 확인할 화면을 열지 못하면 `not-measured`로 남깁니다. 시각적 통합·문구 구체화·불필요한 표현 생략을 제안하되 필요한 제목 구조·접근 가능한 이름·탭과 패널 연결을 보존합니다.

두 주제 모두 개별 사용은 `component-usage`, 동등한 페이지 사이의 정책 차이는 `page-consistency`로 보고합니다. 같은 원인을 화면 크기나 중복 요소 개수만큼 별도 결함으로 부풀리지 않습니다. 검사 지침은 제품을 자동 수정하지 않습니다.

## 테마·색상 의미·대비

같은 계산값의 다른 역할과 별칭·fallback은 [토큰 경로](token-meaning.md), 표시·값·상태의 불일치는 [선택 상태](state-meaning.md), 사용자 색상과 그리기 변경은 [강제 색상](forced-colors.md)으로 구체화합니다. 세 근거를 하나의 색상 점수로 합치지 않습니다.

- **조건:** 지원하는 테마와 hover·focus·selected·disabled·error 등 해당 상태, 실제 배경·중첩 표면·투명도를 확인합니다. 지원하지 않는 테마를 필수로 만들지 않습니다.
- **확인:** 같은 의미의 토큰이 테마와 상태 전환에서도 역할을 유지하는지, 배경·본문·아이콘·경계·초점의 구별이 유지되는지, 오류·선택·상태를 색만으로 구분하는지 확인합니다.
- **판정:** 대비는 채택한 조항별 적용 대상·글자 크기/굵기·상태·예외를 확인합니다. 비활성·장식 요소를 일반 본문과 같은 기준으로 일괄 판정하지 않습니다. 이미지·그라데이션·투명 표면은 실제 합성 배경의 근거가 부족하면 계산을 확정하지 않습니다.
- **출처:** [Atlassian 색 역할과 테마](https://atlassian.design/foundations/color/), [WCAG 색 사용](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color), [텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast).

## 움직임과 사용자 설정

- **조건:** 기본과 움직임 감소 설정, 등장·확대·이동·스크롤 연동 효과 등 요청 대상의 전환을 재현합니다.
- **확인:** 비필수 이동이 줄어드는지, 상태 변화와 조작에 필요한 정보는 남는지, 중단·대체 표현이 문서와 맞는지 확인합니다. 설정 분기 선언만으로 실제 전환을 통과시키지 않습니다.
- **판정:** 필수 움직임과 장식 효과, 자동 시작과 사용자 상호작용에 따른 움직임을 구분합니다. WCAG 2.3.3은 AAA이므로 AA의 필수 조항으로 표시하지 않습니다. 프로젝트가 채택한 움직임 감소 요구는 그 자체의 근거로 적용할 수 있습니다.
- **출처:** [WCAG 상호작용 애니메이션](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions).

## 로딩 중 배치 안정성

정지 비교에 쓸 자료는 [캡처 준비 조건](capture.md)의 실제 연속 구간·조상 전환·선택 자산을 확인합니다. 로딩·전환 자체의 검사에서는 그 상태를 별도 과정 근거로 보존합니다.

- **조건:** 이미지·글꼴·지연 콘텐츠의 로딩 전후, 선택한 스크롤·상태 전환 구간을 기록합니다. 느린 로딩이나 실패를 재현했다면 방법과 영향 범위를 밝힙니다.
- **확인:** 공간 예약과 실제 표시 사이의 차이, 읽던 내용이나 누르려던 행동의 예상치 못한 이동을 확인합니다. 의도된 사용자 전환과 예상치 못한 이동을 구분합니다.
- **판정:** 정적 캡처 한 장으로 이동이 없다고 판정하지 않습니다. CLS 등 측정값을 사용하면 도구·관찰 구간과 로컬 실험인지 실제 사용자 집계인지 밝힙니다. 짧은 로컬 검사로 서비스 전체 Core Web Vitals 통과를 주장하지 않습니다.
- **출처:** [web.dev 배치 이동 최적화](https://web.dev/articles/optimize-cls).

## 정보와 행동의 명확성

- **조건:** 화면의 주요 과업과 실제 콘텐츠, 주요·보조·위험 행동, 취소·이탈·복구 경로를 명세와 연결합니다.
- **확인:** 강조·정보량·문구가 주요 과업을 지원하는지, 같은 행동의 이름과 의미가 페이지마다 일관되는지, 실수하기 쉬운 행동에 알맞은 안내·제약·취소·되돌리기가 있는지 확인합니다.
- **판정:** 버튼 개수나 밀도에 보편적인 합격값을 만들지 않습니다. 모든 행동에 확인창을 강제하지 않고 행동의 영향과 기존 계약을 봅니다. 휴리스틱만으로 판단한 개선 의견은 `review`, 확정된 문구·위계·행동 계약의 위반은 근거를 갖춰 보고합니다.
- **출처:** [NN/g의 상태·일관성·실수 예방·통제·정보 위계 원칙](https://www.nngroup.com/articles/ten-usability-heuristics/).

## 검사 조건과 근거의 재현성

- 재현에 필요한 상태·입력 자료·화면 크기·확대·테마·언어·입력 방법·움직임 설정과 도구·브라우저·OS·글꼴·실행 자산의 식별 근거를 기록합니다. 항목에 무관한 환경값까지 요구하지 않습니다.
- 계획한 조건과 실제 관찰 조건을 구분합니다. 조건을 만들지 못했거나 실제 환경을 확인하지 못했다면 `null`과 이유를 남기고 해당 검사에 미친 영향을 밝힙니다.
- 비교 이미지나 기존 보고서는 원본 기준·생성 조건·확인 범위가 맞는 부분만 재사용합니다. 브라우저·OS·글꼴·테마가 다른 화면의 픽셀 차이를 바로 제품 결함으로 단정하지 않습니다.
- 동적 콘텐츠·커서·애니메이션을 고정하거나 비교에서 가렸다면 영역과 이유를 기록합니다. 검사 대상인 오류·로딩·움직임을 숨긴 채 그 항목을 통과시키지 않습니다.
- 시각 회귀는 채택된 기준 화면과 현재 결과를 비교하는 근거입니다. 화면 전체 픽셀 유사도를 페이지 일치율로 대체하거나, 새 화면을 자동으로 정답으로 승인하지 않습니다.
- 자동 수집 결과와 에이전트 해석·사람의 수용 판단을 구분합니다. 자동 도구가 찾지 못했다는 사실로 접근성 전체가 적합하다고 하지 않습니다.
- **출처:** [Playwright 시각 비교](https://playwright.dev/docs/test-snapshots), [W3C 검사 도구의 역할과 한계](https://www.w3.org/WAI/test-evaluate/tools/selecting/).
