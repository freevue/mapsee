# 토큰의 역할과 참조 경로

계산된 색·간격 값의 일치와 역할에 맞는 토큰 사용을 구분합니다. 토큰 이름의 영어 의미만으로 프로젝트의 용도를 추측하지 않습니다. 서로 다른 역할의 토큰이 같은 값인 상태도 검사 후보입니다.

## setup에서 확인할 기준

기존 DESIGN·토큰 선언·컴포넌트 가이드에서 역할별 공개 토큰, 내부 별칭, 적용 상태·테마·컴포넌트와 허용 예외를 연결합니다. 특정 토큰 재사용이 필수인지, 같은 역할의 별칭·선택적 확장·대체값이 허용되는지 원본 기준을 확인합니다. 토큰을 나열한 것만으로 역할 계약이 있다고 하지 않습니다.

필수 역할·사용 범위가 미정이면 실제 사용과 필요한 결정을 review로 남깁니다. 값이 같다는 이유로 역할을 합치거나 현재 코드의 대체값을 새 표준으로 채택하지 않습니다. 기존 토큰 정본을 연결하고 별도 사전을 중복 작성하지 않습니다.

## lint 절차

1. 실제 요소·상태에서 적용되는 속성·선택자와 호출부의 스타일 소유 범위를 찾습니다. CSS Modules·상속·로컬 변수·미디어·레이어·원본과 빌드 결과의 차이를 구분합니다.
2. 속성에서 로컬 별칭·공개 역할 토큰·실제 값까지 참조 경로와 원본 위치를 남깁니다. var의 fallback이 선언돼 있는 것과 실제로 선택된 것을 구분합니다. 접근할 수 없는 스타일시트나 동적 경로는 추측하지 않습니다.
3. 잘못된 이름·정의 누락·순환·잘못된 역할이 대체값에 가려지는지 확인합니다. CSS의 var 대체는 최종 속성 문법까지 모든 잘못을 복구하는 장치가 아닙니다. 등록 속성·스코프·상속·캐스케이드가 관련되면 실제 브라우저 결과를 확인합니다.
4. 적용한 참조 경로가 프로젝트의 역할 계약과 맞는지 판정합니다. 선언을 전역 사전 하나로 합쳐 가짜 순환을 만들지 않습니다. Tailwind의 빌드 지시문과 실행 CSS의 변수 범위도 분리합니다.

| 사례 | 판정 원칙 |
| --- | --- |
| 오류에는 error 토큰이 필수인데 값이 같은 accent를 사용 | 원본 범위와 경로가 확인되면 mismatch. 같은 계산값으로 면제하지 않음 |
| 허용된 로컬 별칭이 원래 error에 연결 | 해당 역할 경로는 match. 별칭 자체를 위반으로 만들지 않음 |
| 필수 토큰의 오타가 fallback 색으로 가려짐 | 실제 선택과 사용 의무를 확인해 지적. fallback의 존재만으로 일괄 위반하지 않음 |
| 선택적 브랜드 토큰과 문서화된 기본 대체값 | 원본이 허용한 조건이면 match 또는 근거 있는 예외 |
| 역할 계약이 없거나 참조가 동적으로 미확정 | 기준 부재는 review, 확인해야 할 경로를 읽지 못하면 not-measured |

criterion에 역할·상태·원본 문단, evidence에 속성→참조 경로·위치·실제 값·활성 대체값의 근거를 연결합니다. 강제 색상 등 사용자 에이전트의 그리기 단계 변경은 [환경 검사](forced-colors.md)와 구분합니다. 직접 사용은 component-usage, 동등한 페이지 역할의 참조 관계 비교는 page-consistency입니다.
