# 맵시 setup

사용자가 셋업을 요청하면 기존 디자인 기준과 컴포넌트 설명 문서의 상태부터 확인하고 필요한 문서를 구성·보완합니다. 문서가 이미 있어도 점검을 생략하거나 새 문서로 대체하지 않습니다. 플러그인의 취향이나 외부 사례를 프로젝트 규칙으로 복사하지 않습니다. 문서가 없어도 lint가 이 스킬을 자동으로 실행하지 않습니다.

1. 대상 저장소의 에이전트 지침과 기존 문서 구조를 읽습니다. `DESIGN.md` 또는 같은 역할의 진입 문서, 토큰 정의, 컴포넌트 README·사용 가이드·Storybook과 원본 계약의 위치를 찾습니다. 요청 범위의 화면과 공용 컴포넌트를 문서에 대응시키고, 문서가 없는 대상과 열 수 없는 자료도 목록에 남깁니다.
2. [문서 상태와 초기 조사 기준](references/initial-review.md)에 따라 문서의 유무·필수 설명·링크·중복·충돌과 현재 구현과의 차이를 점검합니다. 상태·조작·콘텐츠·환경 변화의 적용 근거·재현 조건·기대 결과도 확인합니다. 실제 토큰 선언·컴포넌트·대표 사용처를 확인하고 문서별 상태, 근거, 필요한 보완을 먼저 보여줍니다. 화면을 실행할 수 없으면 코드 관찰과 시각 확인을 구분합니다.
3. 현재 색상과 시각 요소를 역할별로 요약해 대표 화면과 함께 보여주고, 유지할 것·바꿀 것·예외 중 결정이 필요한 사항만 작은 묶음으로 묻습니다. 사용자 결정 또는 충돌 없는 기존 정본은 `확정`, 코드·화면에서만 찾은 값은 `관찰`, 근거가 없거나 충돌하는 값은 `미결정`으로 기록합니다. 외부 사례는 선택 후보로만 제시합니다.
4. 셋업 요청 범위에서 기존 문서를 우선 보완합니다. 근거가 명확한 링크·누락된 출처·확정 기준의 설명은 바로 고치고, 새 디자인 결정이나 문서와 구현의 충돌은 임의로 해소하지 않습니다. 사용자 답이 필요한 항목을 남기면서 나머지 보완은 마칩니다. 점검만 요청받았다면 수정 대신 제안을 보고합니다.
5. 같은 역할의 진입 문서가 없을 때만 `DESIGN.md`를 만듭니다. 색·글꼴·간격·시각적 위계와 컴포넌트의 시각적 변형·사용 원칙을 필요한 범위에서 적습니다. 기존 타입·props·함수 계약은 원래 문서로 연결하며 복사하지 않습니다. wiki와 인덱스는 수정하지 않습니다. 필요한 설명이 wiki에만 있다면 수정 제안과 원본 링크를 남깁니다.
6. 요청 범위에서 빠진 컴포넌트 설명은 기존 가이드나 진입 문서에 보완합니다. [사용 기준과 재실행](references/initial-review.md#사용-기준과-재실행)에 따라 역할·공용 컴포넌트·공개 경로·필수/권장/허용/미결정·조건·예외·근거를 연결합니다. 점검 전용이면 이 표를 결과에 제안하고 문서는 수정하지 않습니다. 시각적 변형·상태·조합과 [간격·중첩·배치·선택 이유](../lint/references/composition.md)도 필요한 범위에서 설명합니다. 기존 정본을 연결하고 타입·props 계약과 불필요한 새 문서를 중복 작성하지 않습니다. 코드 관찰과 사용자 미채택 후보를 강제 규칙으로 넣지 않습니다.
   [배치 영역별 사용 조건](../lint/references/placement.md)과 [연속 상태 전환 기준](../lint/references/transitions.md)이 대상에 필요하면 기존 가이드에서 부모 영역·크기·변형, 중단·재시도·응답 순서와 기대 결과를 확인·보완합니다. 역할별 차이와 미결정을 보존합니다.
   [캡처 준비 조건](../lint/references/capture.md), [모바일 키보드·고정 UI](../lint/references/mobile-viewport.md), [툴팁·메뉴의 연결과 조작](../lint/references/floating.md)이 해당되면 기존 가이드에서 관찰 조건·접근 경로·유지·닫기 기대 결과를 확인합니다. 합성 환경을 실제 기기 기준으로 채택하지 않습니다.
   [역할별 토큰·별칭·대체값](../lint/references/token-meaning.md), [선택·초점·연결 콘텐츠](../lint/references/state-meaning.md), [강제 색상 지원 범위](../lint/references/forced-colors.md)도 해당 원본과 연결합니다. 허용 예외·수동 활성화·native 입력·지원 미결정을 보존하고 현재 색이 같다는 이유로 역할을 합치지 않습니다.
7. 보완한 문서의 링크·출처·값의 충돌과 처음 발견한 누락을 다시 확인합니다. 같은 입력·결정으로 재실행하면 기존 항목을 찾아 중복·불필요한 재작성·규칙 승격을 피하고, 보완할 근거가 없으면 파일을 수정하지 않습니다. 각 문제를 보완 완료·결정 대기·후속 작업·미검증으로 구분합니다. 구현 검사는 요청 시 [lint](../lint/SKILL.md)로 진행하며 셋업 완료와 구분합니다. 필수 결정이나 핵심 자료가 남으면 부분 구성으로 보고합니다.

마지막에 점검한 문서와 없는 문서, 상태와 근거, 생성·수정한 경로와 보완 전후, 조사한 화면·컴포넌트, 확정·관찰·미결정 사항과 남은 작업을 보고합니다. 코드 수정이나 임의의 디자인 변경은 별도 요청이 있을 때만 합니다.
