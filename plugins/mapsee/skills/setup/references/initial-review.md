# 문서 상태와 초기 조사 기준

이 문서는 setup이 기존 문서의 상태를 점검하고 보완하며 사용자 프로젝트에 맞는 질문을 고를 때 읽습니다. 조사 주제는 요청 범위에 맞춰 선택하며 프로젝트에 자동 적용하는 디자인 규칙이 아닙니다.

## 문서 상태 점검과 보완

파일 존재 여부만으로 준비 완료라고 판단하지 않습니다. 기존 진입 문서와 상세 가이드를 따라 요청 범위의 화면·컴포넌트가 설명되는지 확인합니다. `DESIGN.md`라는 이름이나 특정 문서 도구를 요구하지 않습니다.

| 상태 | 판단 근거와 후속 작업 |
| --- | --- |
| 정상 | 필요한 설명·원본 링크가 있고 확인한 선언·사용처와 모순이 없습니다. 확인 범위를 함께 적고 불필요하게 다시 쓰지 않습니다. |
| 없음 | 요청 범위의 기준 또는 컴포넌트 설명을 찾지 못했습니다. 찾은 경로와 검색 범위를 적고 기존 문서의 적절한 위치에 보완합니다. |
| 보완 필요 | 설명 누락·끊긴 참조·오래된 이름이나 예시·중복 정본·출처 충돌을 구체적으로 찾았습니다. 문제 위치와 근거, 보완 또는 결정할 사항을 적습니다. |
| 확인 불가 | 원본 접근이나 실행 조건이 부족해 확인하지 못했습니다. 이유와 필요한 자료를 남기며 없음·정상으로 간주하지 않습니다. |

문서별로 경로 또는 문서가 없는 대상, 담당 화면·컴포넌트, 상태, 문제 위치와 근거, 보완 내용을 기록합니다. 여러 문제가 있으면 함께 남깁니다. 수정일이 오래됐다는 이유만으로 오래된 문서라고 판단하지 않습니다.

- **DESIGN과 진입 문서:** 적용 범위, 확정·관찰·미결정 구분, 실제 토큰·컴포넌트 가이드·원본으로 연결되는 경로를 확인합니다. 색·글꼴·간격 등 요청 범위에 필요한 기준이 빠졌는지 살핍니다.
- **컴포넌트 설명:** 언제 재사용하는지, 역할별 시각적 변형·조합·예외, 해당되는 로딩·오류·비활성·포커스·좁은 화면 표현, 대표 사용 예가 필요한 만큼 설명되는지 확인합니다. 모든 컴포넌트에 동일한 항목을 강제하지 않습니다.
- **요소 사이의 관계:** [간격·중첩·배치·선택 이유](../../lint/references/composition.md)를 읽고 같은 역할의 여백과 간격 단계, 부모·자식 라운드의 의존 관계, 컴포넌트가 놓인 위치와 선택한 이유가 설명되어 있는지 확인합니다. 숫자 목록만 있고 적용 조건·계산 관계·예외가 빠졌다면 보완 후보로 남깁니다.
- **부모 영역과 흐름:** [배치 영역별 기준](../../lint/references/placement.md)에서 좁은 모달·카드·사이드바의 크기·변형·줄바꿈·스크롤 조건을 확인합니다. [연속 상태 전환](../../lint/references/transitions.md)에서 실패 후 재시도·성공, 대기 중 닫기·이탈·늦은 응답의 정책과 단계별 기대 결과를 확인합니다. 현재 구현의 값을 채택된 정책으로 승격하지 않습니다.
- **격자와 영역별 상태:** [격자 기준](../../lint/references/grid.md)의 채택 여부·적용 대상·원점·오차와 [영역별 화면](../../lint/references/surfaces.md)의 기본·처리 중·오류·완료 상태, 상태별 캡처와 전환 기대가 필요한 범위에서 설명되는지 확인합니다. 4px나 고정 높이를 일괄 채택하지 않습니다.
- **상태와 조작의 기준:** [상태와 조작 검사](../../lint/references/interaction.md)에 따라 상태 완전성·입력 오류와 복구·키보드/레이어·클릭/터치·확대 조건의 설명과 근거를 확인합니다. 재현할 상태·입력·조작과 기대 결과가 빠져 있으면 보완합니다.
- **변화와 재현 조건:** [콘텐츠·환경 변화와 재현성](../../lint/references/resilience.md)에 따라 긴 콘텐츠·언어·테마·움직임 감소·로딩 중 배치 안정성·정보와 행동의 명확성이 해당 프로젝트에서 어떻게 정의되는지 확인합니다. 기준 화면·도구·환경·가상 자료의 출처와 재사용 조건도 정리합니다.
- **중복 표현과 줄바꿈:** [연속된 의미 중복과 반응형 줄바꿈](../../lint/references/resilience.md)에 따라 탭·본문 제목 등의 반복을 허용하는 역할·조건, 좁은 부모 영역의 제목·탭·버튼 줄바꿈 기대와 예외가 설명되어 있는지 확인합니다. 실제 관찰과 미결정 기준을 구분하며 반복·여러 줄을 일괄 금지하지 않습니다.
- **검사용 잔여물:** [검사용 문구·로그 기준](../../lint/references/debug-residue.md)에 따라 정상 사용자 안내·운영 로그와 임시 검사 표시·진단 로그의 경계를 기존 계약에서 확인합니다. 문서가 없다는 이유로 검사용 잔여물을 허용하거나 정상 로그를 일괄 금지하지 않습니다.
- **현재 상태 대조:** 문서의 토큰 이름·값과 예시를 실제 선언·공개 계약·대표 호출부에 연결합니다. 문서의 옛 경로나 없는 variant처럼 구체적인 차이를 기록합니다. 실제 렌더를 보지 않았다면 시각·동작 확인은 미검증으로 남깁니다.
- **색·선택의 의미:** [토큰 경로](../../lint/references/token-meaning.md)의 역할·별칭·활성 fallback과 예외, [선택 상태](../../lint/references/state-meaning.md)의 native/ARIA·표시·값·콘텐츠·초점 관계, [강제 색상](../../lint/references/forced-colors.md)의 지원·판정 범위를 기존 문서에서 확인합니다. 기준 부재를 임의 채택으로 해소하지 않습니다.
- **수집·모바일·부유 UI:** [캡처 준비](../../lint/references/capture.md)의 조상 전환·선택 자산·기대 상태, [모바일 입력](../../lint/references/mobile-viewport.md)의 키보드 전후 접근·고정 영역, [툴팁·메뉴](../../lint/references/floating.md)의 트리거·유지·닫기 조건이 해당되면 기존 가이드에서 확인합니다. 관찰을 확정 규칙으로 올리거나 실제 표시를 확인하지 못한 키보드를 합성 결과로 통과시키지 않습니다.
- **보완 범위:** 출처가 분명한 링크와 설명은 기존 문서에 반영합니다. 코드와 문서가 다르다는 이유만으로 문서를 코드에 맞추지 않습니다. 기존 확정 기준은 보존하고 차이와 결정할 사항을 기록합니다. 충돌 없는 확정 근거가 없으면 새 디자인 규칙은 만들지 않습니다.
- **문서 소유권:** 같은 규칙은 기존 정본으로 연결합니다. wiki와 인덱스, 제품 코드는 바꾸지 않고 props·타입·함수 계약을 복사하지 않습니다. wiki의 결함은 원본 위치와 개선 제안으로 보고하며 편집 가능한 디자인 문서에 시각적 사용 설명을 보완합니다.

예를 들어 버튼 가이드가 삭제된 `accent` 토큰을 가리키면 실제 선언과 원본 기준을 확인합니다. 확정된 이름 변경이 있으면 링크·예시를 보완하고, 대체 색의 역할이 미정이면 그 사실을 남깁니다. 구현에서 많이 쓴 색을 새 표준으로 정하지 않습니다.

## 사용 기준과 재실행

기존 DESIGN·가이드의 적절한 위치에서 역할별 사용 기준을 찾거나 보완합니다. 표의 각 행은 역할·대상 범위, 공용 컴포넌트와 공개 import 경로, 필수/권장/허용/미결정, 적용 조건·예외, 원본 근거를 연결합니다. 점검 전용이면 같은 내용을 보고서에 제안합니다. 별도 파일·모든 컴포넌트의 목록을 일률적으로 요구하지 않습니다.

- **필수:** 프로젝트가 그 위치·조건에서 사용 의무를 명시한 경우입니다. 공용 컴포넌트가 존재하거나 많이 사용된다는 사실만으로 필수로 정하지 않습니다.
- **권장:** 정본이 기본 선택으로 권고하지만 대안을 허용하는 경우입니다. 권장과 허용된 대안을 필수 위반으로 바꾸지 않습니다.
- **허용:** 원본이 명시한 native DOM·앱 래퍼·특수 역할의 예외입니다. 라이브러리 내부 DOM과 화면 호출부의 의무를 구분합니다.
- **미결정:** 역할의 재사용 기준이 없거나 출처가 충돌하는 경우입니다. 확인한 사용 현황은 관찰로 남기며 강도를 추측하지 않습니다.

위 구분과 원본 결정의 `확정/관찰/미결정`을 혼동하지 않습니다. 강도의 근거를 다른 문서에서 가져오면 경로·문단을 연결하고 공개 props·타입 설명은 복제하지 않습니다. 조건부 렌더·래퍼의 전달·복합 구성 계약은 해당 원본 가이드를 연결합니다.

동일한 기준·코드·사용자 결정으로 다시 셋업하면 기존 행과 설명을 먼저 찾습니다. 누락·새 차이가 없으면 그대로 두고 점검 결과만 보고합니다. 실행일·버전 이력만 추가하려고 DESIGN을 바꾸거나, 관찰을 확정 규칙으로 올리지 않습니다. 입력이 바뀐 경우에만 영향받은 항목을 보완하고 원본 근거·확정 기준을 보존합니다.

## 먼저 확인할 자료

- 사용자 제공 디자인 원본, 선호·비선호 화면과 현재 제품의 대표 화면을 찾습니다. 원본을 볼 수 없으면 그 사실을 기록합니다.
- 색상 원시값과 의미별 토큰, 글꼴·크기·굵기, 간격·크기·모서리·그림자, 아이콘·이미지, 움직임 설정을 찾습니다. 선언만 있는 값과 실제 화면에서 쓰는 값을 구분합니다.
- 공용 UI 컴포넌트와 화면 전용 요소를 구분합니다. 시각적 변형·상태, 사용하는 토큰과 사용처를 조사합니다. 공개 props·타입·동작 계약은 기존 출처를 참조합니다.
- 대표 화면에서 데스크톱·좁은 화면, 기본·로딩·빈 결과·오류·비활성·포커스 상태 중 실제로 확인 가능한 범위를 기록합니다.

## 사용자에게 묻는 방법

조사한 화면이나 코드 값을 먼저 보여주고 결정이 필요한 것만 묻습니다. 한 번에 관련 질문 2~4개를 묶습니다. 막연한 취향 대신 현재 사례와 선택지를 사용합니다.

예를 들어 검색 화면의 버튼은 의미별 강조 토큰을 쓰고 설정 화면의 같은 역할 버튼은 원시 색상값을 쓴다면, 두 화면을 보여주고 통일할지 의도적인 차이로 둘지 묻습니다. 공용 버튼의 한 변형이 여러 화면에 쓰이는데 문서가 없다면, 그 변형을 공식 사용 원칙으로 둘지 먼저 확인합니다.

1. **방향:** 현재 화면에서 유지할 부분과 어색한 부분은 무엇인가요? 참고할 화면과 피할 화면은 무엇인가요? 제품이 차분함·밀도·강조 중 무엇을 우선해야 하나요?
2. **색·타입·형태:** 실제 사용 중인 색의 역할과 대비, 제목·본문의 위계, 간격의 밀도, 모서리·그림자·아이콘 방식 중 어떤 것을 표준으로 둘까요? 테마별 예외가 있나요?
3. **컴포넌트:** 같은 기능에 기존 컴포넌트를 언제 재사용하고 언제 새 변형을 만들까요? 새 컴포넌트의 props는 어떤 시각적 선택을 허용하고 무엇을 고정할까요?
4. **화면 사용:** 주요 행동과 정보의 우선순위, 로딩·빈 화면·오류의 문구와 행동, 작은 화면의 재배치, 포커스·키보드 조작과 움직임의 강도를 어떻게 정할까요?

답변이 없는 항목은 `미결정`으로 남깁니다. 기존 구현은 `관찰`로 기록하며 사용자 승인 없이 표준으로 승격하지 않습니다.

## 미결정 기준의 제안

반복해서 미결정으로 남는 항목은 현재 관찰·적용 역할·조건·예외·기대 결과·선택할 사항으로 정리합니다. 점검 전용이면 제안은 결과에만 둡니다. 채택하지 않은 제안은 기준 문서의 강제 규칙이 아닙니다.

- Dialog는 배경 조작을 막는 모달인지 함께 사용할 수 있는 비모달인지 먼저 구분합니다. 모달을 선택할 경우 진입 초점·Tab 범위·Escape/닫기·복귀 대상과 사라진 트리거의 대안을 제안합니다. 현재 초점 처리가 없다는 설명을 자동 면제나 새 위반 기준으로 바꾸지 않습니다.
- 중첩 표면은 실제 부모·자식·간격·border·모서리별 조건을 표시합니다. 채택 후보는 안쪽 경계를 기준으로 곡선 관계를 유지하는 방법과 역할상 독립 반경을 유지하는 방법으로 설명합니다. pill·아바타 등 독립 모양은 구분하고, 외곽 반경에서 padding만 빼는 공식을 모든 표면에 강제하지 않습니다.
- 선택 이유·배치가 불분명하면 관련 정보·주요 행동·상태의 관계를 현재 화면과 연결해 제안합니다. 이미 있는 props 문서를 복제하거나 별도 규칙 파일을 의무화하지 않습니다.

## 가이드에 제안할 세부 주제

필요한 주제만 실제 전후 사례와 함께 제안합니다. 사용자가 채택한 선택만 사용 가이드의 규칙이 됩니다.

- **색상:** 원시값과 의미별 토큰의 관계, 배경·텍스트·강조·상태색의 용도, 테마별 대응.
- **타이포그래피:** 제목과 본문의 위계, 줄바꿈과 긴 텍스트, 숫자 정렬, 문구의 대소문자와 버튼 이름.
- **배치와 선택:** 정보 그룹 사이의 거리와 내부 여백의 단계, 시각적 정렬, 중첩 표면의 여백·라운드 관계, 화면별 밀도와 주요 행동의 위치, 컴포넌트 선택 이유와 허용되는 대안.
- **상호작용:** hover·focus·pressed·disabled, 로딩·빈 화면·오류의 피드백, 움직임의 목적·속도·중단 가능성.
- **접근과 반응형:** 의미 있는 HTML 요소, 키보드·포커스, 이미지 설명, 대비, 좁은 화면의 순서와 터치 영역.

각 규칙에는 적용 대상, 채택 이유, 좋은 예와 피할 예, 검증 가능한 관찰 기준을 적습니다. 수치나 취향은 프로젝트에서 결정한 것만 넣습니다. 화면이 어색하다는 인상만으로 위반을 만들지 않고, 근거가 부족하면 사용자에게 선택을 묻습니다.

외부 표준은 채택 여부·버전·조항·등급·예외를 기록하고, 프로젝트 기준·관찰·휴리스틱 제안과 구분합니다. 요청받은 검사 주제를 추가하는 것과 특정 표준의 모든 조항을 채택하는 것은 별개입니다. 합의된 동작은 적용 근거·재현 조건·기대 결과로 문서화하고, 현재 구현이 실제로 충족하는지는 lint에서 별도로 판정합니다.

[Interfaces의 치트 시트](https://interfaces.dev/cheat-sheet)와 [디테일 사례](https://interfaces.dev/magazine/issues/details-that-make-interfaces-feel-better)는 전후 비교와 질문 방식의 참고 자료입니다. 그곳의 개인적 선호나 수치를 프로젝트의 기본 규칙으로 복사하지 않습니다.

## setup 완료 조건

- 기존 문서의 상태와 요청 범위의 문서 누락을 확인했고, 보완한 항목과 남은 문제의 근거·처리 상태를 보고했습니다. 기존 문서가 있다는 이유로 점검을 생략하지 않았습니다.
- 진입 문서에서 확정된 토큰·컴포넌트·사용 가이드의 정본을 정확히 찾을 수 있습니다.
- 요청한 범위의 시각적 기준과 사용 원칙을 확인할 수 있고, 기존 구현 계약의 출처로 연결됩니다. 별도의 props·타입 문서 완성을 요구하지 않습니다.
- 가이드의 강제 규칙은 사용자 결정이나 충돌 없는 프로젝트 정본에 근거합니다. 관찰·미결정은 강제 규칙과 분리됩니다.
- 문서 링크와 값의 충돌을 검사했습니다. 코드와 실제 화면을 확인한 범위, 확인하지 못한 범위를 따로 보고합니다.
- 요청 범위의 상태·조작·환경 변화에 대한 적용 근거와 재현 조건·기대 결과가 연결되며, 근거가 부족한 조건은 관찰·미결정으로 남아 있습니다.

요청 범위의 필수 디자인 결정이나 확인하지 못한 핵심 자료가 남아 있으면 `부분 구성`으로 보고합니다. 기존 링크나 구현 차이를 해결하지 못했다면 원인과 후속 작업을 남깁니다. 셋업 완료를 실제 화면 검사 통과로 보고하지 않습니다.
